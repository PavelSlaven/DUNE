## Цель

У юнита `UNIT_LAUNCHER` (Ракетница) цвет Дома нарисован с собственной светотенью (швы панелей, блики, тени), как у Девиатора `UNIT_DEVIATOR` и Танка `UNIT_TANKBASE` и `UNIT_TANKTOP`, и окрашенная площадь больше, чем в паке `resources/bin/data/sdl_data_hd4.dat` на HEAD ветки `codex/u33-launcher-colour`. Для этого перерисованы тело `UNIT_LAUNCHER` и маска цвета Дома `HM_UNIT_LAUNCHER` во всех 8 направлениях. Тень `UNIT_LAUNCHER_SHADOW`, размер и положение силуэта в каждом направлении и код движка не изменены. Работа идёт в две части: часть А — варианты тела и маски, листы и числа для выбора ведущим; часть Б — сборка выбранного варианта, установка двух записей в пак, новый тест и сдача. Числовые условия приёмки — в разделе «Критерии приёмки (числа)» задания.

## Критерии приёмки (числа)

Условия (а), (б), (в), (г) не зависят от цвета Дома: движок красит пиксель цветом Дома, умноженным на отношение яркости пикселя тела к средней яркости тела под маской. Эти условия считаются один раз на атлас (таблица T1). Условие (г) считается для каждого из трёх цветов Дома (таблица T2): где отношение яркости к средней больше 255 / (house_c · 166/255), канал цвета Дома упирается в 255, и цвет выходит ровной заливкой — это и есть плоский цвет на снимке владельца.

Определения (скрипт считает только по ним):

1. Атлас — PNG 1024 × 128: 8 клеток 128 × 128 в одну строку. Направление k занимает пиксели x от 128·k до 128·k + 127. Направления: k0 — восток, k1 — северо-восток, k2 — север, k3 — северо-запад, k4 — запад, k5 — юго-запад, k6 — юг, k7 — юго-восток. Атлас другого размера — блок `## Q-U33-01`.
2. Непрозрачный пиксель тела — пиксель атласа `UNIT_LAUNCHER` с альфой больше 127. Для Девиатора и Танка то же правило на атласах `UNIT_DEVIATOR`, `UNIT_TANKBASE`, `UNIT_TANKTOP`.
3. Сила маски `s` пикселя: `s = (Am/255) · (max(Rm, Gm, Bm)/255)`, где `Rm, Gm, Bm, Am` — каналы пикселя атласа `HM_UNIT_LAUNCHER` в той же позиции. Для Девиатора — `HM_UNIT_DEVIATOR`, для Танка — `HM_UNIT_TANKBASE` и `HM_UNIT_TANKTOP`.
4. Яркость тела `L = (0.299·R + 0.587·G + 0.114·B)/128`, где `R, G, B` — каналы пикселя атласа тела в диапазоне 0–255.
5. `avg` движка — средняя `L` по всем пикселям атласа с `s ≥ 0.99` и альфой не равной нулю; таких пикселей нет — `avg = 166/255`.
6. Цвет пикселя после покраски: `colour_c = clamp(house_c · L · (166/255) / avg, 0, 255)` для каждого канала `c`, округление `lround`; итог `c' = c·(1 − s) + colour_c·s`; пиксели с `s ≤ 0` или с альфой ноль не меняются. Формулы 3–6 записаны по `src/utils/Graphics.cpp` строки 378–458 и `src/utils/FactionTint.hpp`. Перед написанием скрипта сверь их с кодом; код расходится с записью — бери формулу из кода и запиши расхождение в журнал и в «Не проверено» сдачи.
7. `house_c` — цвета Домов из `resources/game.ini`, секция `[HOUSES]`, ключи `*_MINIMAPCOLOR`: Ордос (0, 255, 0), Атрейдес (0, 0, 255), Харконнен (255, 0, 0). Прочти значения из файла; значения в файле отличаются от этих — бери из файла.

Таблица T1 (на атлас, по 8 клеткам вместе):

- **(а) `eff`** = сумма `s` по непрозрачным пикселям тела, делённая на число непрозрачных пикселей тела. Требование: `0.40 ≤ eff ≤ 0.55`. Ориентир ведущего для нынешнего `UNIT_LAUNCHER`: 0,378.
- **(б) `stdL_over_avg`** = стандартное отклонение (генеральное, `ddof=0`) значений `L` по непрозрачным пикселям тела с `s ≥ 0.5`, делённое на `avg` того же атласа (определение 5). Требование: `stdL_over_avg` нового Ракетницы не меньше 0,8 от `stdL_over_avg` Девиатора; Девиатор считается тем же скриптом по записям `UNIT_DEVIATOR` и `HM_UNIT_DEVIATOR` пака на HEAD. Справочно в T1 — `stdL` без деления.
- **(в) рамка** в каждом направлении k: рамка непрозрачных пикселей тела — четыре числа (минимальный x, минимальный y, максимальный x, максимальный y внутри клетки 128 × 128). Требование: каждое из четырёх чисел нового тела отличается от соответствующего числа клетки `UNIT_LAUNCHER` пака на HEAD не больше чем на 2 пикселя. Отклонение направления `bbox_dev` — наибольшая из четырёх абсолютных разностей.
- Справочно в T1: `stdL` и флаги `a_ok`, `b_ok`, `c_ok` (`c_ok` истинно, когда `bbox_dev ≤ 2` во всех 8 направлениях).

Таблица T2 (на атлас и на цвет Дома, по 8 клеткам вместе):

- `cvY` = стандартное отклонение, делённое на среднее значение, величины `Y = 0.299·R' + 0.587·G' + 0.114·B'` по непрозрачным пикселям с `s ≥ 0.5` после покраски по определению 6.
- **(г) `clip`** = доля этих пикселей, у которых хотя бы один канал `house_c · L · (166/255) / avg` до `clamp` больше 255. Требование для каждого из трёх цветов Дома: `clip` нового Ракетницы не больше `clip` Девиатора для того же цвета плюс 0,05. Флаг `d_ok` истинен, когда требование выполнено для всех трёх цветов.

Строки отчёта (и для T1, и для T2): `LAUNCHER_HEAD` (запись пака на HEAD), `DEVIATOR`, `TANKBASE`, `TANKTOP` (записи пака на HEAD; у Танка — две строки, по телу и по башне) и по одной строке на каждую пару части А (`B1a`, `B1b`, `B2a`, `B2b`). Числа из раздела «Что есть» — ориентиры ведущего, ты их перемеряешь по определениям выше, в сдаче — только твои числа.

Скрипт пишет `.tmp/u33-sheets/numbers.tsv`: столбцы `row_id`, `k`, `eff`, `stdL`, `stdL_over_avg`, `bbox_dev`, `iou`, `share`, а для T2 — `house`, `cvY`, `clip`; строки — каждый `row_id` в каждом направлении `k` от 0 до 7 и ещё строка `k = all` (общие значения; для `bbox_dev` в строке `all` — наибольшее по направлениям). `iou` и `share` берутся из `metrics.txt` пробной сборки пары; у строк без сборки в этих столбцах стоит `-`. Ведущий может выбрать для разных направлений разные попытки, поэтому числа по направлениям обязательны.

## Что есть

- Причина (issue #80). Движок красит пиксель цветом Дома, умноженным на яркость тела под маской (`src/utils/Graphics.cpp:378-458`). Тело Ракетницы под маской — один материал почти с ровной яркостью, поэтому цвет Дома выходит плоским. Правка U21 (PR #69) сузила только маску `HM_UNIT_LAUNCHER`. Ещё одно обстоятельство: с коммита `ed45d11b` тело под маской приведено к нейтральному серому с яркостью в четверть (скрипт `codex-direct/U21/tone.py`). Новый шаг этого задания тон-шаг не повторяет и тон-картинки не использует.
- Решение владельца 2026-11-04 (по игре за Атрейдес): «Ракетная установка не прокрашена нормально, как остальные», «Там ещё и окраса не хватает».
- Ориентиры ведущего по нынешнему паку (8 кадров вместе, альфа больше 0; ты перемеряешь по определениям выше с альфой больше 127):

|---|---|---|---|
| `UNIT_LAUNCHER` | 0,378 | 0,1131 | avg 0,2916; cv 0,388 |
| `UNIT_DEVIATOR` | 0,288 | 0,2856 | avg 0,8366; cv 0,341 |
| `UNIT_TANKBASE` | 0,380 | 0,2095 | cv 0,286 |
| `UNIT_TANKTOP` | 0,328 | 0,2097 | нет |

- Образцы для сравнения освещены сверху: Девиатор и Танк. Новое тело освещается так же, сверху.
- Атласы Ракетницы в паке `resources/bin/data/sdl_data_hd4.dat`: `UNIT_LAUNCHER`, `HM_UNIT_LAUNCHER`, `UNIT_LAUNCHER_SHADOW`. Тень строится сборкой из альфы тела по правилу `shadow_rule` (сдвиг 3, альфа 56, цвет 7, 6, 5).
- Описание: `tools/units3d/units/UNIT_LAUNCHER/unit.json`. Поля: `scale` 0.972842; `scale_factor` 0.923 в k4 и 1.058 в k6; `share_corridor` [0.312, 0.512]; восемь записей кадров, у каждой поля `row`, `k`, `attempts`, `pick`, `recolour`. - Инструмент перерисовки: `tools/units3d/redraw.py build <папка с unit.json> <пустая папка вывода>`.
  - Маска получается из картинки `recolour`: зелёный пиксель — `G − max(R, B) ≥ 80`; маска двоичная, умножается на альфу тела, RGB маски 255.

- Установка: `tools/units3d/install.py --atlases <папка с atlases.json> --pack resources/bin/data/sdl_data_hd4.dat` заменяет только записи, перечисленные в `atlases.json`. Чтение пака — `tools.hd_assets.read_pack` и `tools.hd_assets.decode_image`.

## Правила генерации (для корневой нити и для каждого помощника)

1. Один вызов ImageGen — одна входная картинка.
2. Сразу после вызова скопируй выходной файл из `$CODEX_HOME/generated_images` в `.tmp/u33-gen/` байт в байт под именем из шага 3 или 4: без изменения размера и без пересжатия. Выходной файл бери по пути, который вернул вызов ImageGen, а не по времени изменения: несколько помощников пишут в одну папку одновременно. В журнал `.tmp/u33-gen/log-G<n>.tsv` (`<n>` — номер помощника, корневая нить пишет `log-G0.tsv`, если работает сама) добавь строку из полей через табуляцию: время UTC, слово `copied`, имя результата, путь источника, sha256 результата.
3. Измерения (только для проверки, на копии): силуэт — пиксели, у которых расстояние RGB до (255, 0, 255) больше 60; зелёный пиксель — `G − max(R, B) ≥ 80`; результат приводится к размеру входной картинки сжатием Lanczos. Угловые пиксели (четыре угла картинки) должны удовлетворять `R ≥ 150`, `B ≥ 150`, `G ≤ 100`.
4. Плохая попытка этапа 1 — выполнено хотя бы одно: картинка не квадратная; угловые пиксели не проходят; число связных областей силуэта площадью не меньше 1 % площади картинки не равно 1 (`scipy.ndimage.label`); силуэт касается крайней строки или крайнего столбца картинки; IoU силуэта с силуэтом входной картинки меньше 0.95; отношение `std(L)/mean(L)` по пикселям силуэта (`L` по определению 4) меньше 1,15 от того же отношения входной картинки.
5. Плохая попытка этапа 2 — выполнено хотя бы одно: картинка не квадратная; угловые пиксели не проходят; IoU силуэта с силуэтом входной картинки меньше 0.95; доля зелёных пикселей от пикселей силуэта меньше 0,30 или больше 0,65.
6. Плохая попытка — один повтор. Заменённую картинку перенеси в `.tmp/u33-gen-first/` с тем же именем; результат повтора получает основное имя. Повтор тоже плохой — оставь его под основным именем, в журнал запиши строку `bad` с причиной и иди дальше.
7. Отказ модерации — один повтор. Второй отказ — попытка пропущена: в журнал строка `skipped` с первыми 200 символами текста отказа. Пропущенное направление в паре заменяется попыткой с той же буквой промпта и другой буквой попытки (пропущена `B1a` в k3 — берётся `B1b` в k3); замену запиши в сдачу. Пропущены обе попытки — пара неполная: пробную сборку этой пары не делай, запиши причину.
8. Общий предел — 96 вызовов ImageGen, повторы включены. Предел достигнут — генерация останавливается, дальше идёт то, что есть, и в сдаче записано число вызовов и что осталось без результата.
9. ImageGen недоступен, или не принимает входную картинку — блок `## Q-U33-01` и стоп.
