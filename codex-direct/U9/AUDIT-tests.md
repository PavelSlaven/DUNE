## Находки

**Н1. macOS: библиотека движка без `D2TM_CLANG` — сборка упадёт.** Обязательная.
- Где: `tests/UnitRenderFixture.cmake:22–36`.
- Что не так: `d2tm_unit_frame_engine` компилирует весь `D2TM_SRC`, включая `src/ini.cpp` и `src/utils/cTimeManager.cpp`, без определения `D2TM_CLANG=1`. Игра получает его на Apple Clang отдельно (`CMakeLists.txt:107–111`); без него `src/platform.h:15–16` даёт 0. Тогда собираются ветки `#else`: `std::from_chars` для `float` (`src/ini.cpp:81` и далее) и `std::chrono::zoned_time` с `current_zone()` (`src/utils/cTimeManager.cpp:28–51`). Это ровно тот код, который проект отключил для Clang коммитами `f761c305` и `bfa33fcf`. Ни один прежний тест не компилирует эти файлы, поэтому на macOS их без флага ещё никто не собирал. Ожидаемый итог: шаг Build в обоих заданиях macOS `build_pr.yml` и в macOS-сборке `release.yml` красный уже на текущей ветке, до реализации.
- Что ожидается: `if(APPLE AND CMAKE_CXX_COMPILER_ID MATCHES "Clang") target_compile_definitions(d2tm_unit_frame_engine PUBLIC D2TM_CLANG=1) endif()`. В общем виде: библиотека повторяет определения, которые игра получает по платформам.
- Причина: исполнитель.

**Н2. Windows: проверка `renderStrechSpriteF` всегда ложна — верная реализация не слинкуется.** Обязательная.
- Где: `tests/UnitRenderFixture.cmake:3–13`, `:54–56`; `tests/UnitDrawRecorder.cpp:83–104`.
- Что не так: исходник проверки включает `drawers/SDLDrawer.hpp`, тот — `<SDL2/SDL.h>`, тот — `SDL_main.h`. На Windows без `SDL_MAIN_HANDLED` он переименовывает `main` в `SDL_main`. `check_cxx_source_compiles` линкует исполняемый файл без `SDL2main` и падает. Пробой MinGW g++ 16.2 на равнозначном исходнике получил `undefined reference to WinMain`. Значит, на MSYS2 `D2TM_UNIT_FRAME_HAS_FRACTIONAL_DRAWER` всегда ложь. На `main` это безвредно. С верной реализацией `cUnit.o` из библиотеки ссылается на `SDLDrawer::renderStrechSpriteF`, а регистратор этот метод не определяет. Тогда не линкуются все три записывающих теста: `unit_hd_frame_draw`, `unit_frame_interactions`, `unit_draw_regression`. Шаг Build падает в задании Windows (`build_pr.yml`) и в Windows-сборке `release.yml`. Исправить это исполнитель реализации не сможет: тесты заморожены. Причина известна проекту: прежние тесты определяют `SDL_MAIN_HANDLED` (`tests/CommandBindingsTests.cpp:1`, `tests/FontCoverageTests.cpp:1`, `tests/RenderTargetStateTests.cpp:1`), новые цели — тоже (`UnitRenderFixture.cmake:79`, `:95`), а проверка — нет. Ветка «метод есть» не прогонялась ни на одной платформе: объявления пока нет.
- Что ожидается: `set(CMAKE_REQUIRED_DEFINITIONS -DSDL_MAIN_HANDLED)` вокруг проверки или `CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY`. Плюс громкий отказ: если `SDLDrawer.hpp` по тексту объявляет `renderStrechSpriteF`, а проверка ложна, — `FATAL_ERROR`. Проще без проверки при конфигурации: в регистраторе `#if __has_include("utils/UnitSpriteLayout.hpp")`. До заморозки — разовая проба на servak на копии с добавленным объявлением.
- Причина: исполнитель.
