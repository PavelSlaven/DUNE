# Задание U9-T1 — приёмочные тесты кадра 176 × 176 Осадного танка

Режим: **«План у ревьюера»** (см. «Режимы задания» в конце). Исполнитель: Codex `gpt-6.1-sol` `high`; помощники — субагенты `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/u9f`, ветка `codex/u9-frame`, HEAD — текущий `main` (коммит с этим файлом или новее). Коммитов не делай: ведущий коммитит по списку из сдачи.

## Цель

Приёмочные тесты поведения из задания `codex-direct/U9/TASK-frame.md` (раздел «Поведение», пункты 1–6) с поправками ведущего `codex-direct/U9/PLAN-OK-frame.md`. Реализации в ветке нет: тесты пишутся по поведению. Тесты изменяемого поведения падают на коде ветки `main`; тесты неизменного поведения (регрессионные) на коде `main` проходят. Каждый новый тест падает хотя бы на одной неверной реализации из раздела «Неверные реализации», на верной реализации проходит. Имена новых полей, файлов и функций берутся из одобренного плана `codex-direct/U9/PLAN-frame.md` (разделы 1–3); поправки `PLAN-OK-frame.md` сильнее плана, а требования этого задания сильнее обоих.

## Общие правила ожиданий

- **Эталон не из проверяемого кода.** Ожидаемые `src`, `dest`, `getVisualRectangle()` и размеры кадров вычисляются в тесте по формулам этого раздела из таблицы размеров, записанной в тесте: `bmp_width`, `bmp_height`, `bmp_frames` каждого типа юнита из `src/utils/cIniGameRessouces.cpp` коммита `bb2f1b37`. Нельзя брать ожидание из `getVisualRectangle()`, из текущих `sUnitInfo[...]`, из функций `UnitSpriteLayout.hpp` или другого нового кода.
- **Масштабы.** Зум камеры `z` — каждый из {0,8; 1,0; 1,3; 2,0}; масштаб мира `s` — каждый из `ManualWorldScales` = {1,00; 1,10; 1,25; 1,50} (`src/utils/WorldScale.hpp:6`). Матрица тестов строк 1–4 таблицы ниже — все 16 пар.
- **Видимый прямоугольник** (формула `bb2f1b37`) для логического размера `w × h`: `ow = lround(z · w)`, `oh = lround(z · h)`, `vw = lround(ow · s)`, `vh = lround(oh · s)`, `visual = {draw_x − (vw − ow) / 2, draw_y − (vh − oh) / 2, vw, vh}` с целочисленным делением. У Осадного `w × h` = 36 × 36: на экране это 36 × 36 только при `z = 1`, `s = 1`; при других масштабах — по формуле, например при `z = 1`, `s = 1,25` — 45 × 45.
- **Назначение HD-кадра** 176 × 176 при плотности 4 (44 логических пикселя): `W = lround(lround(44 · z) · s)` и так же `H`; `dest = {visual.x + (visual.w − W) / 2,0; visual.y + (visual.h − H) / 2,0; W; H}` дробными числами (`SDL_RenderCopyF`, поправка 3 `PLAN-OK-frame.md`). Пример с половиной пикселя: `z = 0,8`, `s = 1,1` — `visual.w = 32`, `W = 39`, `dest.x = visual.x − 3,5`.

## Неверные реализации

Каждый новый тест обязан падать хотя бы на одной из них; каждая обязана ронять хотя бы один тест.

1. Код ветки `main` без правок.
2. HD-кадр меняет и `getVisualRectangle()` (видимый прямоугольник Осадного при `z = 1`, `s = 1` — 44 × 44).
3. Механизм — ветка «тип юнита равен `SIEGETANK`» в `cUnit::draw`, хотя функции `UnitSpriteLayout.hpp` общие: `TANK` с HD-кадром в тесте рисуется по-старому.
4. Исходный прямоугольник по старой логической рамке: шаг столбца и строки 36 логических пикселей (144 пикселя атласа) вместо 44 (176 пикселей атласа) или размер 36 × 36 вместо 44 × 44.
5. Назначение выровнено по левому верхнему углу видимого прямоугольника, а не по центру.
6. Башня берёт направление корпуса.
7. В классической графике Осадный рисуется с HD-кадром.
8. Инструмент режет старые кадры по `frame` [176, 176] вместо `reference_frame`.
9. Медиана считается с M = 176.
10. `pack` или `install.py` принимают новый размер у любой записи.
11. Контракт даёт `frame_hd4` = `frame_classic × 4` у Осадного или 176 × 176 у всех.
12. Источник 176 × 176 верный, центр верный, назначение прежнее по размеру (`visual.w × visual.h`) — картинка не увеличена.
13. У тени изменены прозрачность или режим смешивания при прежних `src` и `dest`; или у `CARRYALL` пропало смещение тени на 24.
14. Установщик отвергает у чужой записи только размер 1408 × 176, а другой новый размер принимает; или пишет пак до отказа.
15. Якорь переносится на (16, 12) вместо (16, 16).
16. Дробное назначение округляется до целого (при `z = 0,8`, `s = 1,1` — `dest.x = visual.x − 3` или `− 4` вместо `− 3,5`).

Основа мутантов 2–16 — верная реализация, которой в ветке нет, и писать её ты не должен. Поэтому для мутантов 2–16 сдай таблицу «мутант → тесты, которые обязаны упасть, и почему» по тексту тестов, без прогона, с пометкой «не проверено прогоном». Прогон мутанта 1 (код `main`) обязателен для всех новых тестов, Python и C++, включая тест на программном рендерере SDL.

## Чем проверить

- Python, прогон на коде `main`: `PYTHONDONTWRITEBYTECODE=1 TMPDIR="$PWD/.tmp/unittest-tmp" D2TM_PACK_DIR="$PWD/resources/bin/data" /srv/dune/venv/bin/python -m unittest discover -s tools/units3d/tests -v`. Без `D2TM_PACK_DIR` класс контракта пропускается (`test_unit_contract.py:823`) — такой прогон не считается. В сдаче: строки вывода; тесты изменяемого поведения красные по заявленной причине; регрессионные зелёные; число пропущенных (`skipped`) — 0 у новых тестов и у `test_unit_contract.py`, иначе — `Q` с причиной пропуска.
- C++: копия рабочей копии в `.tmp/` без папки `resources/` (на её месте — символическая ссылка на `resources/` рабочей копии: полная копия занимает 2,1 ГБ при запасе диска servak около 4 ГБ над порогом остановки), сборка по рецепту `/srv/dune/deps/sdl2/README.txt` (прочитай его целиком) и прогон `ctest` с `SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software SDL_AUDIODRIVER=dummy`. На коде `main`: исполняемые файлы, которым нужен новый интерфейс, не собираются — в сдаче строка ошибки компилятора с именем отсутствующего заголовка или поля, это красный результат этих тестов; регрессионные тесты строк 3 и 4 собираются и проходят; прежние тесты CTest зелёные. Тест на программном рендерере инициализирует только `SDL_INIT_VIDEO`: `SDL_INIT_EVERYTHING` в песочнице servak падает на UDEV. После прогона удали копию: `rm -rf` по её буквальному пути.
- CI: ведущий пушит ветку; прогон CTest в CI — дополнительная проверка, а не замена прогона на servak.
- `sha256sum` каждого нового и изменённого тестового файла — строки для `tools/units3d/tests/ACCEPTANCE.sha256` (Python) и отдельный список для C++.
