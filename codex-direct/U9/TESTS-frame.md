## Общие правила ожиданий

- **Эталон не из проверяемого кода.** Ожидаемые `src`, `dest`, `getVisualRectangle()` и размеры кадров вычисляются в тесте по формулам этого раздела из таблицы размеров, записанной в тесте: `bmp_width`, `bmp_height`, `bmp_frames` каждого типа юнита из `src/utils/cIniGameRessouces.cpp` коммита `bb2f1b37`. Нельзя брать ожидание из `getVisualRectangle()`, из текущих `sUnitInfo[...]`, из функций `UnitSpriteLayout.hpp` или другого нового кода. Ожидания полос здоровья и спайса, группы и опыта (строка 3) тест выписывает формулами из функций `draw_health`, `draw_spice`, `draw_group`, `draw_experience` коммита `bb2f1b37` (`cUnit.cpp:574–720`).
- **Текстуры и отладка.** Текстуры корпуса, тени, башни, маски, `FOCUS` и `SYMB_PICKMEUP` в тестах строк 2–4 — синтетические объекты `Texture`, которые тест сам подкладывает; ожидаемая текстура вызова — указатель, подложенный тестом. Флаг `game.m_drawUnitDebug` в тестах выключен (при включённом `cUnit::draw` добавляет отладочные вызовы, `cUnit.cpp:858`).
- **Положение юнита** (формула `bb2f1b37`, `cUnit.cpp:510–530`, `cMapCamera.h:81–94`): `draw_x = round(z · (pos_x − viewportStartX + (32 − w) / 2))`, `draw_y = round(z · (pos_y − viewportStartY + (32 − h) / 2) + heightOfTopBar)`, где `(32 − w) / 2` — целочисленное деление C++ (дробная часть отбрасывается к нулю), `round` — `std::round`, `w × h` — логический размер из таблицы.
- **Масштабы.** Зум камеры `z` — каждый из {0,8; 1,0; 1,3; 2,0}; масштаб мира `s` — каждый из `ManualWorldScales` = {1,00; 1,10; 1,25; 1,50} (`src/utils/WorldScale.hpp:6`). Матрица тестов строк 1–4 таблицы ниже — все 16 пар выбранных настроек. В формулы ниже подставляется действующий масштаб мира: в HD — выбранный `s`, в классике — всегда 1,0 (`getWorldScaleFactor()`, `src/cGame.h:294` коммита `bb2f1b37`).
- **Видимый прямоугольник** (формула `bb2f1b37`) для логического размера `w × h`: `ow = lround(z · w)`, `oh = lround(z · h)`, `vw = lround(ow · s)`, `vh = lround(oh · s)`, `visual = {draw_x − (vw − ow) / 2, draw_y − (vh − oh) / 2, vw, vh}` с целочисленным делением. У Осадного `w × h` = 36 × 36: на экране это 36 × 36 только при `z = 1`, `s = 1`; при других масштабах — по формуле, например при `z = 1`, `s = 1,25` — 45 × 45.
- **HD-кадр** `Fw × Fh` пикселей атласа при плотности 4 — это `Lw × Lh` логических пикселей, `Lw = Fw / 4`, `Lh = Fh / 4`. Исходный прямоугольник в единицах API рисования: `{d · Lw, iFrame · Lh, Lw, Lh}`, где `d` — направление слоя; `SDLDrawer` умножает его на плотность. Назначение: `Dw = lround(lround(Lw · z) · s)`, `Dh = lround(lround(Lh · z) · s)`, `dest = {visual.x + (visual.w − Dw) / 2,0; visual.y + (visual.h − Dh) / 2,0; Dw; Dh}` дробными числами (`SDL_RenderCopyF`, поправка 3 `PLAN-OK-frame.md`). У Осадного `Fw × Fh` = 176 × 176, `Lw × Lh` = 44 × 44. Пример с половиной пикселя: Осадный при `z = 0,8`, `s = 1,1` — `visual.w = 32`, `Dw = 39`, `dest.x = visual.x − 3,5`.
- **HD-кадры, которые тест задаёт другим типам** (строка 2): `TANK` — 160 × 160 (40 × 40 логических при прежних 32 × 32); `HARVESTER` — 352 × 224 (88 × 56 при прежних 80 × 52). Атласы для них — синтетические, согласованные с этими кадрами.
- **Строки анимации.** Значения `iFrame` в матрицах: 0, а у типов с `bmp_frames` больше 0 ещё 1 и `bmp_frames`. Атлас для записи вызовов не нужен: `src` — число по формуле.

## Неверные реализации

Каждый новый тест обязан падать хотя бы на одной из них; каждая обязана ронять хотя бы один тест.

1. Код ветки `main` без правок.
2. HD-кадр меняет и `getVisualRectangle()` (видимый прямоугольник Осадного при `z = 1`, `s = 1` — 44 × 44).
3. Механизм — ветка «тип юнита равен `SIEGETANK`» в `cUnit::draw`, хотя функции `UnitSpriteLayout.hpp` общие: `TANK` с HD-кадром в тесте рисуется по-старому.
4. Исходный прямоугольник по старой логической рамке: шаг столбца и строки 36 логических пикселей (144 пикселя атласа) вместо 44 (176 пикселей атласа) или размер 36 × 36 вместо 44 × 44.
5. Назначение выровнено по левому верхнему углу видимого прямоугольника, а не по центру.
6. Башня берёт направление корпуса.
7. В классической графике Осадный рисуется с HD-кадром.
8. Инструмент режет старые кадры по `frame` [176, 176] вместо `reference_frame`.
9. Медиана считается с M = 176.
10. `pack` или `install.py` принимают новый размер у любой записи.
11. Контракт даёт `frame_hd4` = `frame_classic × 4` у Осадного или 176 × 176 у всех.
12. Источник 176 × 176 верный, центр верный, назначение прежнее по размеру (`visual.w × visual.h`) — картинка не увеличена.
13. У тени изменены прозрачность или режим смешивания при прежних `src` и `dest`; или у `CARRYALL` пропало смещение тени на 24.
