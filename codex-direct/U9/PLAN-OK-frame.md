# PLAN-OK-U9-frame

План `codex-direct/U9/PLAN-frame.md` (сдача задания `codex-direct/U9/TASK-frame.md`) одобрен ведущим с поправками ниже. Поправки сильнее текста плана.

1. **Неизменность остальных юнитов и классики** доказывается без двух сборок и без попиксельной матрицы. Тест записывает вызовы рисования из `cUnit::draw` (метод `SDLDrawer`, текстура, `src`, `dest`) для каждого типа юнита из `src/utils/cIniGameRessouces.cpp`, всех направлений тела и башни, используемых строк анимации, графики HD и классической и масштабов мира из теста `hd_presentation_selection`. Ожидание — формула `bb2f1b37`, записанная в тесте явно: `src = {bmp_body · bmp_width, bmp_height · iFrame, bmp_width, bmp_height}`, `dest = getVisualRectangle()`, тот же целочисленный метод рисования. У Осадного в классике ожидание то же. Если записать вызовы без правки кода продукта нельзя — вопрос `Q`. Пиксельный тест один: Осадный в HD на программном рендерере SDL, контрольные метки на границах кадров (`unit_render_pixels` плана); он идёт в CI.
2. **Цвет Дома по Р28** входит в коммит 4 плана; пункт 7 плана «новая раскладка цвета Дома — отдельная работа» отменён. Описания Осадного берут перекраски, выбранные ведущим: у кадра k — `units-gen/UNIT_SIEGEBASE/siegebase_recolour9_k<k>.png` и `units-gen/UNIT_SIEGETOP/siegetop_recolour9_k<k>.png` (суммы — `codex-direct/U9/gen/`). Поле `share_corridor`: корпус `[0.10, 0.45]`, башня `[0.15, 0.60]`. Причина: доля старой маски Осадного по кадрам — 0,04–0,06 у корпуса и 0,02–0,03 у башни, а по Р28 цвет Дома несут крупные плиты (доля зелёного в силуэте новых перекрасок — 0,20–0,26 и 0,32–0,43); старые маски больше не образец доли.
3. Развилка центрирования: дробное назначение через `SDL_RenderCopyF` — принято.
4. Правило масштаба: F = медиана отношений ширин рамок тела Девастатора и корпуса Осадного по направлениям, F = 1,205373515108, корпус `scale` 1,179349500917, башня 1,148390687555 — принято. Обрезка в `build` — вопрос `Q`, без `"fit"`.
5. Запуск CTest в четырёх заданиях `build_pr.yml` — принят.
6. Отсечение по видимой области остаётся по `getVisualRectangle()` — принято как ограничение: выступ картинки на 4 логических пикселя за рамку у края экрана может пропасть на кадр раньше.

Дальше по плану: приёмочные тесты — отдельный исполнитель по разделу «Поведение» задания и этим поправкам; затем правки.
