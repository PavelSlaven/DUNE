## Что исправить

1. **Определения платформы у библиотеки движка.** Игра на Apple с компилятором Clang получает `D2TM_CLANG=1` (`CMakeLists.txt:107–111`). Без него `src/platform.h:15–16` даёт 0, и `src/ini.cpp` и `src/utils/cTimeManager.cpp` собираются по веткам, которые проект для Clang отключил (`std::from_chars` для `float`, `std::chrono::zoned_time`). Библиотека `d2tm_unit_frame_engine` (`tests/UnitRenderFixture.cmake:22`) этого определения не получает, и сборка на обоих заданиях macOS упадёт. Исправление: библиотека получает те же определения, что игра, при тех же условиях — сейчас это `D2TM_CLANG=1` при `APPLE` и `CMAKE_CXX_COMPILER_ID MATCHES "Clang"`. Предупреждения компилятора игры библиотеке не нужны.
2. **Проверка `renderStrechSpriteF` на Windows.** Исходник проверки (`tests/UnitRenderFixture.cmake:9–12`) включает `drawers/SDLDrawer.hpp`, а через него `<SDL2/SDL.h>` и `SDL_main.h`. На Windows без `SDL_MAIN_HANDLED` заголовок переименовывает `main` в `SDL_main`, линковка проверки падает (`undefined reference to WinMain`), и `D2TM_UNIT_FRAME_HAS_FRACTIONAL_DRAWER` там всегда ложь. С верной реализацией `cUnit` вызывает `SDLDrawer::renderStrechSpriteF`, регистратор этот метод не определяет, и три записывающих теста не линкуются. Исправление:
   - определение `SDL_MAIN_HANDLED` в проверке (`CMAKE_REQUIRED_DEFINITIONS`);
   - громкий отказ: если текст `src/drawers/SDLDrawer.hpp` содержит `renderStrechSpriteF`, а проверка дала ложь, — `message(FATAL_ERROR ...)` с именем проверки и путём заголовка.
3. **Цель `unit_sprite_layout_tests` без библиотеки движка.** Цель (`tests/UnitRenderFixture.cmake:86–99`) ни с чем не линкуется. Договор реализации допускает определения функций `UnitSpriteLayout.hpp` и в заголовке, и в отдельном `src/utils/UnitSpriteLayout.cpp`; во втором случае тест не слинкуется. Исправление: цель линкуется с `d2tm_unit_frame_engine` так, чтобы собирались обе формы реализации. Новый `.cpp` попадает в `D2TM_SRC` сам: `src/CMakeLists.txt:1` собирает исходники через `file(GLOB_RECURSE ...)`.
4. **Внутренние проверки пиксельного теста выполняются всегда.** В `tests/UnitRenderPixelsTests.cpp:144` метки краёв, метка соседа, утечка и цвет Дома проверяются только при `bboxMatches`. На `main` рамка не совпала, поэтому эти четыре проверки ни разу не выполнялись. Исправление: каждая из четырёх проверок выполняется при любом исходе проверки рамки, координаты проб считаются от ожидаемого прямоугольника, отказ каждой проверки печатается своей строкой, а тест в конце падает, если отказала хотя бы одна проверка.
5. **Перенос якоря на кадре с другим центром.** В `tools/units3d/tests/test_siege_frame.py` смещение после переноса проверено только у кадра `r0k0` (`:166`), у которого центр старой рамки совпадает с якорем. Добавь проверку `params["frames"]["r0k1"]["offset"]`. Ожидаемое значение посчитай сам по эталону и формулам теста и запиши расчёт в сдачу. Аудит получил `[-458, -441]`; если твой расчёт даёт другое число, напиши оба числа и где расходятся расчёты.
6. **Имена файлов фикстуры при параллельном CTest.** Имена файлов фикстуры строятся по `SDL_GetTicks()` (`tests/UnitFrameFixture.cpp:219`) в общей папке. При `ctest -j` два процесса могут получить одно имя, и один удалит файлы другого. Исправление: у каждой цели своя подпапка `${D2TM_UNIT_FRAME_FIXTURE_ROOT}/<имя цели>` или номер процесса в имени файла — выбери одно.
7. **Пустая строка в конце файлов.** `git diff --check e4e703d7 HEAD` даёт «new blank line at EOF» в 12 новых файлах C++ и CMake. Убери лишнюю пустую строку; после правок `git diff --check e4e703d7` по рабочей копии пуст.
