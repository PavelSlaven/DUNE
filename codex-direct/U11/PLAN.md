### 2. Автоматический переход и захват кадра

**Рекомендация: режим отладки по отдельному аргументу командной строки + SDL `dummy/software`.** Он позволяет подготовить нужное состояние, дождаться законченной отрисовки и сохранить итоговый framebuffer без внешнего управления мышью.

Рассмотренные варианты:

| Вариант | Вывод |
|---|---|
| Отдельный аргумент отладки | Даёт воспроизводимые игровые сцены, сохранения, исходы и положения прокрутки. Рекомендован. |
| Xvfb с подачей ввода | Доступны Xvfb, xwd и ffmpeg; xdotool отсутствует. Потребуются собственная подача ввода и ожидание переходов. Остаётся резервным вариантом; запуск не проверен. |
| SDL без дисплея | Подтверждён пробой при `SDL_VIDEODRIVER=dummy`, `SDL_RENDER_DRIVER=software`, `SDL_AUDIODRIVER=dummy` и ограниченной инициализации SDL в режиме отладки. |

Обычная инициализация `SDL_INIT_EVERYTHING` в песочнице завершилась ошибкой UDEV. В **копии исходников внутри `.tmp/`** создан прототип `--ui-audit-probe <путь PNG>`: только при этом аргументе инициализируются VIDEO, AUDIO, TIMER и EVENTS. Раскладка и отрисовка экранов не изменялись.

Будущий массовый режим будет:

1. Читать перечень сцен и сочетание запуска.
2. Подготавливать миссию через существующие загрузчики, фабрики и игровые обработчики.
3. Использовать фиксированные случайные данные и управляемое время только внутри режима отладки.
4. Проверять готовность состояния и завершение перехода.
5. После `presentFrame`, перед `SDL_RenderPresent`, читать итоговый кадр через `SDL_RenderReadPixels` и сохранять его через `IMG_SavePNG`.
6. Завершаться с ошибкой при неподготовленной сцене, неверном размере, отсутствии HD4 или ошибке записи.

Размер поверхности берётся из `SDL_GetRendererOutputSize`. Штатный F11 для массового захвата не использую: его код создаёт поверхность по логическим размерам игры.

Для разрешений выше рабочего стола SDL `dummy` потребуется **только в режиме отладки** отключить ограничение окна размерами рабочего стола в `cScreenInit`. Реальный размер каждого PNG проверяется отдельно.

Режим покроют новые CTest: запуск главного меню во всех сочетаниях, проход полного каталога сцен, проверка покрытия строк титров, отказ для неизвестной сцены и проверки отключённого режима. Штатные тесты и их ожидания сохраняются.

В этой пробе уже прошли **21/21 CTest**, включая `ui_audit_probe_png`: [лог](/srv/dune/worktrees/u11/.tmp/probe/ctest-prototype.log).

**Известный дефект:** обязательный кадр игровых настроек при 1024 × 768, русском языке, HD и обоих масштабах «Авто» получит логический холст 800 × 600 и масштаб 128 %. Кадр сохранит целиком строки настроек и кнопки Save/Load. Геометрия `OptionsMenuLayout` перед съёмкой не исправляется.

### 3. Переключение сочетаний

Источник — `GameSettings`, `loadSettingsFromIni`, `cHandleArgument`, `RenderScale` и `WorldScale`.

Для каждого запуска создаётся отдельный рабочий каталог в `.tmp/ui-audit/`. Игра ищет конфигурацию рядом с исполняемым файлом, поэтому одного изменения текущего каталога оболочки недостаточно.

В локальном `settings.ini` задаются:

```ini
[SETTINGS]
ScreenWidth=<ширина>
ScreenHeight=<высота>
FullScreen=false
RenderScale=0
WorldScale=0
Language=ru
GraphicsMode=HD
```

Язык меняется на `en`, графика — на `Classic`. Остальные секции берутся из копии исходного `resources/bin/settings.ini`. Разрешение дополнительно передаётся штатными аргументами `-windowed -screenWidth … -screenHeight …`.

`game.ini` копируется из `resources/game.ini`; правила игры между сочетаниями не меняются. Данные, кампании и карты доступны через ссылки для чтения. Сохранения, музыка для проверочной сцены, журналы и PNG создаются только в `.tmp/`.

### 4. Сборка на servak

Рецепт `/srv/dune/deps/sdl2/README.txt` прочитан целиком. Заголовки находятся в:

- `/srv/dune/deps/sdl2/root/usr/include/SDL2`;
- `/srv/dune/deps/sdl2/root/usr/include/x86_64-linux-gnu`.

Библиотеки SDL2, SDL2_image, SDL2_mixer и SDL2_ttf, а также CMake-конфигурации находятся под `/srv/dune/deps/sdl2/root/usr/lib/x86_64-linux-gnu`.

Проверенные команды настройки и сборки:

```sh
P=/srv/dune/deps/sdl2/root/usr
L=$P/lib/x86_64-linux-gnu
export TMPDIR="$PWD/.tmp/probe/tmp"

cmake --fresh -S .tmp/probe/source -B .tmp/probe/build \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++-14 \
  -DCMAKE_PREFIX_PATH="$P" -DCMAKE_BUILD_TYPE=Release \
  "-DCMAKE_CXX_FLAGS=-I$P/include -I$P/include/x86_64-linux-gnu" \
  "-DCMAKE_EXE_LINKER_FLAGS=-L$L -Wl,-rpath-link,$L"

timeout 1800 cmake --build .tmp/probe/build -j 32

SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software \
SDL_AUDIODRIVER=dummy LD_LIBRARY_PATH="$L" \
timeout 180 ctest --test-dir .tmp/probe/build --output-on-failure
```

Исходники скопированы в `.tmp/probe/source`, поскольку CMake записывает `src/include/config.h` в исходное дерево. `resources` подключены ссылкой для чтения.

Результаты:

- GCC 14.2.0, Release: сборка за **19,01 с**, код выхода 0.
- До прототипа: **20/20 CTest**.
- Пересборка прототипа: **5,40 с**.
- С прототипом: **21/21 CTest за 8,41 с**.
- Пробный запуск и захват: **8,23 с**.
- Каталог сборки: **24 МБ**.

[Лог сборки](/srv/dune/worktrees/u11/.tmp/probe/build-gcc14.log), [лог пробного запуска](/srv/dune/worktrees/u11/.tmp/probe/run-prototype.log).

Недостающих пакетов для проверенного способа не обнаружено. Новые установки и загрузки не требуются.

Продолжительность уточняется по первым полным сочетаниям.

Пробный PNG занимает **1 067 872 байта**. Экстраполяция его размера по числу пикселей всего набора даёт **5,34 ГиБ PNG**; для листов и индекса заложено ещё **0,5 ГиБ**. Фактическое сжатие других экранов не измерено.

Сейчас свободно **9 028 726 784 байта**, около **8,41 ГиБ**. Для указанного прогноза и остатка 5 ГиБ нужно около **10,84 ГиБ свободного места**.

**Развилка:** перед массовой съёмкой рекомендую освободить место до этого уровня либо согласовать другое хранилище артефактов. До ответа владельца внешние каталоги не используются. Проверка места выполняется перед каждым PNG; при остатке менее 5 ГБ работа останавливается. Полученные кадры для продолжения съёмки не удаляются.
