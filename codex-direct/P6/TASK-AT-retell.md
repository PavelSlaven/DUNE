### Атаки

Красные случаи ниже рассматриваются независимо: остальные части реализации сохраняются исправными. Это контрпримеры по структуре проверок, а не результаты выполненных прогонов.

**К1. Нарушение дословного переноса заголовков.** Добавить пустую строку в один из двух переносимых заголовков форка, сохранив поведение. Все семь тестов это пропустят, хотя требование дословной копии нарушено: ни один тест не сравнивает содержимое файлов.

**К2. Неверная альфа целевого цвета.** Возвращать правильный RGB, но всегда нулевую альфу из `houseMaskTargetColor`. Тест № 3 проверяет только RGB, хотя для Сардаукаров контракт требует альфу `255`, а для остальных — исходный `minimapColor` целиком.

**К3. Неверная обработка остальных Домов.** Правильно обработать четыре проверенных идентификатора, а для остальных возвращать пурпурный цвет. Тест № 3 пропустит нарушение требования возвращать `minimapColor` для любого идентификатора, кроме `SARDAUKAR`.

**К4. Отсутствие проверок указателей.** Оставить правильную обработку обычных поверхностей, но разыменовывать `nullptr` вместо возврата `false`. Тесты № 4, № 5 и № 7 не вызывают `applyHouseMaskTint` с нулевыми указателями.

**К5. Проверка только ширины маски.** Отклонять несовпадение ширины, но принимать несовпадение только высоты. Тест № 5 проходит: в нём различаются ширины, а высоты одинаковы.

**К6. Принятие неправильного формата target.** Поддерживать окраску и возвращать `true` для формата, отличного от RGBA32. Все проверяемые поверхности в № 4 и № 5 имеют RGBA32; обязательный отказ не проверяется.

**К7. Среднее каналов вместо максимума маски.** Вычислять силу маски через среднее `mr`, `mg`, `mb`. В № 4 и № 5 все маски серые, поэтому среднее совпадает с максимумом; № 7 содержимое полученных текстур не проверяет.

**К8. Игнорирование альфы маски.** Вычислять силу только по RGB маски. В № 4 единственная маска с нулевой альфой также имеет нулевые RGB, а остальные маски непрозрачны; различие формул не проявится.

**К9. Включение прозрачного пикселя в среднюю яркость.** При вычислении средней яркости учитывать полностью замаскированные пиксели с нулевой альфой target. Тест № 4 пропустит ошибку: прозрачный пиксель имеет яркость серого `150`, совпадающую со средним серых `200` и `100`.

**К10. Неверный порог полной маски.** Для средней яркости использовать только `strength == 1`, вместо `strength >= 0.99F`. В № 4 нет маски с силой между `0.99` и `1`; № 7 пиксели не сверяет.

**К11. Неправильная альфа полупрозрачных пикселей.** После окраски заменять любую ненулевую альфу на `255`. В № 4 представлены только альфы `0` и `255`, поэтому нарушение сохранения промежуточной альфы останется незамеченным.

**К12. Отсутствие фактической окраски в `Graphics`.** В `createHouseTexture` правильно находить маску, создавать отдельную копию нужного размера и плотности, но не применять окраску. Тест № 7 проверяет указатели и метаданные; правильная отдельная функция `applyHouseMaskTint` позволяет пройти № 4.

**К13. Неправильное масштабирование.** Создавать текстуры с ближайшим соседом вместо `SDL_SCALEMODE_LINEAR` при плотности больше единицы. № 7 не запрашивает режим масштабирования.

**К14. Плотность всегда равна четырём.** Всегда записывать в создаваемую текстуру `density = 4`. Единственный проверяемый объект `Graphics` в № 7 имеет именно эту плотность.

**К15. Игнорирование переданного цвета в `Graphics`.** В обоих методах `Graphics` всегда использовать пурпурный цвет вместо `houseColor`. Все вызовы этих методов в № 7 передают пурпурный цвет; других цветов этот тест не различает.

**К16. Отсутствие запасного варианта `getTexture`.** Возвращать `nullptr` из `getHouseTexture`, если `createHouseTexture` не смогла создать окрашенную текстуру. № 7 проверяет отсутствие маски только прямым вызовом `createHouseTexture` для песка; соответствующий вызов `getHouseTexture` отсутствует.

**К17. Утечка кэша.** Сохранять и повторно возвращать правильные текстуры, но не удалять их при уничтожении `Graphics`. Семь перечисленных тестов не проверяют освобождение ресурсов; отдельный анализатор утечек в задании не указан.

**К18. Лишние флаги.** Вернуть правильные записи для двенадцати зданий, `nullptr` для пяти отрицательных примеров, а для остальных непроверенных значений возвращать запись `RADAR`. № 6 не проверяет универсальное требование `nullptr` вне таблицы.

**К19. Неправильное место строки в CMake игры.** Добавить `utils/HouseMaskTint.cpp` в рабочий список исходников, но не сразу после `utils/Graphics.cpp`. Все семь поведенческих тестов могут пройти; точное требование расположения строки ими не проверяется.

**К20. API существует, игровое отображение его не использует.** Реализовать весь проверяемый API, но оставить отрисовку юнитов, флагов и поверхности без подключения новой функциональности. Семь тестов вызывают функции непосредственно и не проверяют игровой путь; это обход цели шага П6, хотя перечисленный API может быть полностью исправен.

По предоставленному тексту я не могу доказать безусловный зелёный контрпример для именно указанного настоящего пака и дословных заголовков форка. Их содержимое не приведено. Следующие случаи показывают зависимость теста от дополнительных предпосылок, но не доказывают, что эти предпосылки ложны в рабочей копии.

**З1. В паке отсутствует маска юнита.** Контрактная реализация возвращает `nullptr` для `UNIT_QUAD`, если запись `HM_UNIT_QUAD` отсутствует, и правильно работает для остальных записей. № 7 падает на `REQUIRE(tinted != nullptr)`, хотя API соблюдён; применимость случая к заданному паку не проверена.

**З2. В паке имеется маска песка.** Контрактная реализация создаёт окрашенную текстуру для `TERRAIN_SAND`, если в паке существует соответствующая `HM_`-запись. № 7 отвергает её требованием `nullptr`; наличие этой записи в заданном паке неизвестно.

**З3. У флага отсутствует маска.** Контрактная реализация возвращает обычную текстуру через предусмотренный запасной вариант `getTexture`, когда маски флага нет. № 7 отвергает правильный результат проверкой отличия указателей; отсутствие маски в заданном паке не установлено.

Отдельное расхождение относится к **критерию прогона B**, а не к честной реализации API: при разрешённом LFS-указателе тест № 7 должен выполнить `SKIP`, поэтому требование ровно четырёх проваленных тестов B не выполнится. Для указанной рабочей копии задание явно обещает настоящие данные, поэтому это ограничение переносимости сценария B, а не доказанный сбой на заданной машине.
