### Т1. `tools/upstream/tests/test_merge_classic_packs.py`

Проверяет скрипт шага 4 задания П2 запуском `python -m tools.upstream.merge_classic_packs` через `subprocess` из корня рабочей копии на синтетических паках во временном каталоге.

- Синтетические паки тест пишет своим кодом по формату D2TM: подпись `D2TM`, число записей `uint16`, каталог записей `<40s4sII` (имя, расширение, смещение, размер; little-endian), затем данные; смещение отсчитывается от начала данных. Модуль `tools.hd_assets` для записи синтетических паков не используется.
- Случаи, каждый — отдельный метод:
  1. запись изменена только форком — в результате запись FORK1, `source` = `fork`;
  2. запись изменена только апстримом и апстрим добавил запись в конец — порядок UP1, `source` = `upstream`, у добавленной `upstream` = `added`;
  3. обе стороны изменили запись по-разному — код 1, в `--out-dir` нет файлов, stderr содержит путь пака и ключ;
  4. обе стороны изменили запись одинаково — код 0, запись в результате;
  5. форк добавил запись; форк удалил запись; форк переставил записи — по коду 1 в каждом из трёх вариантов;
  6. две записи с одним именем — ключи `X#1` и `X#2` в отчёте;
  7. результат равен паку UP1 — выходной файл побайтно равен файлу UP1; результат равен паку FORK1 — побайтно равен файлу FORK1. Входной файл в этих случаях записан с данными в порядке, обратном каталогу, чтобы побайтная копия отличалась от перезаписи;
  8. таблица наличия файла: только UP1; только FORK1; FORK1 и UP1 без BASE, равные и разные; файл BASE без файла FORK1; файл BASE без файла UP1 — результат по таблице задания П2;
  9. пути `x_hd4.dat` и `scenes/hd4/y.dat` не попадают ни в `--out-dir`, ни в отчёт;
  10. заголовок и столбцы отчёта — как в задании П2, включая строку пака, взятого целиком;
  11. ошибка аргументов — код 2.

### Т2. `tools/upstream/tests/test_align_hd4_packs.py`

Проверяет скрипт шага 5 задания П2 запуском `python -m tools.upstream.align_hd4_packs` через `subprocess` на синтетических паках и заголовках. Синтетические паки — тем же своим кодом, что в Т1; данные записей — PNG, которые тест создаёт через Pillow.

- Случаи:
  1. раскладка: заголовок с константами 0–3; в паке форка записи с именами констант 0, 1 и 3, лишняя запись `HM_X` на индексе 2 и лишняя запись `HM_Y` на индексе 4; имя константы 2 есть в списке. Ожидание: 0, 1, 3 — записи форка; 2 — `classic_x4`; 4 — `HM_Y`; 5 — `HM_X`. Отчёт — заголовок, `source`, `fork_index` и `sha256` по заданию П2;
  2. данные `classic_x4`: декодированная картинка результата по размеру и пикселям равна `hd_assets.scale_image(<классическая картинка>, 4)`. Модуль `tools.hd_assets` импортируется внутри этого метода; отдельный случай — для классической картинки в режиме `P` с прозрачностью и для картинки `RGBA`;
  3. формы строк заголовка: `#define`, `constexpr int`, `inline constexpr int`, `static constexpr int`, с комментарием после числа и после `;`;
  4. ошибки, каждая — код 1, нет файлов `--out` и `--report`: пропуск значения; два имени с одним значением; имени константы нет ни в паке форка, ни в списке; имя из списка не использовано; у записи классического пака на позиции другое имя; запись форка после `N` с именем константы;
  5. результат равен паку форка — выходной файл побайтно равен входному (входной записан с данными в обратном порядке);
  6. список читается по имени файла `--out`; ключ другого пака не влияет на результат;
  7. ошибка аргументов — код 2.

### Т3. `tools/upstream/tests/test_port_packs_data.py`

Проверяет настоящие файлы рабочей копии после исполнения задания П2. Если файл пака — указатель LFS (первая строка `version https://git-lfs.github.com/spec/v1`), тест пропускается через `skipTest` с причиной. Если файла нет — тест падает.

- **Классические паки.** Файл `tests/data/classic_packs_expected.tsv`, заголовок `pack	index	name	extension	sha256`. Строки — для паков `sdl_audio.dat`, `sdl_data.dat`, `sdl_gfxeditor.dat`, `sdl_inter.dat`, `sdl_mentat.dat`, `sdl_world.dat` в раскладке, которую дают правила слияния задания П2 на паках `BASE`, `FORK1` и `UP1`. Ожидание строишь своим кодом в `.tmp/p2t/`, не скриптом исполнителя. Тест: `hd_assets.read_pack` каждого пака `resources/bin/data/` даёт те же строки.
- **HD4-паки.** Файл `tests/data/hd4_packs_expected.tsv`, заголовок `pack	index	name	extension	width	height	sha256	source`. Строки — для четырёх графических HD4-паков в раскладке шага 5 задания П2 (константы `UP1`, паки тега `v0.8.0-ru-hd.10`, список из шага 6) и для 18 паков `scenes/hd4/` тега без изменений. `pack` — путь относительно `resources/bin/data/`. `source` — `fork` или `classic_x4`; у `classic_x4` `sha256` = `-`. Ожидание строишь своим кодом в `.tmp/p2t/`.
  - Тест: каждый из 22 паков рабочей копии совпадает со строками по индексу, имени, расширению, размеру картинки и `sha256` строк `fork`.
  - Строки `classic_x4`: картинка равна `hd_assets.scale_image(<картинка записи с тем же индексом и именем классического пака рабочей копии>, 4)` по размеру и пикселям.
  - Число строк `fork` каждого пака равно числу записей этого пака в теге: 241, 144, 51, 36 и числа сцен из пункта 5 отчёта разведки.
- **Файлы без изменений.** sha256 файла `sdl_world_hd4.dat` и каждого из 18 паков сцен равен sha256 файла тега. sha256 файла `sdl_world.dat` — `ebf869028eae8d477e03f368c8a4d5e7040c5b204a151386792fa61c9f77aaa3`.
- **Картинки апстрима.** Для каждой константы заголовков `src/data/gfxdata.h`, `src/data/gfxinter.h`, `src/include/gfxmentat.h`, `src/include/gfxworld.h` запись с индексом, равным её значению, в соответствующем HD4-паке имеет имя этой константы. Каждая константа `src/include/gfxeditor.h` стоит в списке `tools/upstream/classic_without_hd.json` под ключом `sdl_gfxeditor.dat`. Содержимое этого файла равно объекту шага 6 задания П2, записанному в тесте.
- **LFS.** `git check-attr filter` даёт `lfs` для 22 HD4-паков и не `lfs` для шести классических паков и для паков `resources/bin/data/scenes/sdl_*.dat`.

Тест Catch2 в исполняемом файле `d2tm_tests`; файл добавляется в его список источников в `tests/CMakeLists.txt`. Путь к корню исходного дерева тест получает из CMake.

- Тест читает `tests/data/hd4_packs_expected.tsv`. Для каждого из 22 паков открывает `resources/bin/data/<pack>` классом `DataPack` апстрима (`src/utils/cDataPack.hpp`) без изменений его кода:

## Комментарии в коде

Категорически запрещено писать комментарий по принципу «полезен, если верен и относится к делу». По умолчанию комментария нет; он должен доказать право на существование: только неочевидное «почему» — инвариант, причина обхода, ссылка на внешнее ограничение. Пересказ кода, планы и история — нет. Внутренние номера находок, планов и решений (`F7`, `A-11b`, `D88`) в комментарий не писать: суть словами.
