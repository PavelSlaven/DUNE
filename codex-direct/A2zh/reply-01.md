```cpp
struct UnitFrameRectangle {
    int x;
    int y;
    int width;
    int height;

struct UnitFrameLayout {

inline UnitFrameLayout calculateUnitFrameLayout(
```

### Требования к реализации

1. В `s_UnitInfo` сразу после `bmp_height` добавляются два `int`: `hd_bmp_width`, `hd_bmp_height`. В общем цикле они обнуляются. Только у `SIEGETANK` после классической высоты задаются два последовательных присваивания литерала `176`.

2. `calculateUnitFrameLayout` включает HD-ветвь только при положительных обеих HD-сторонах и `texturePixelWidth == 8 * hdWidth`. Иначе возвращает классическую вырезку и неизменный `visual`.

   В HD-ветви размеры источника равны `hdWidth / textureDensity` и `hdHeight / textureDensity`. Экранные размеры вычисляются двумя последовательными `std::lround` с приведением каждого результата к `int`; оба произведения используют `float`. Смещение относительно `visual` делится на два по правилам целочисленного деления C++. Центры совпадают с допустимой погрешностью половины экранного пикселя.

3. В `draw()` сохраняется строка `const cRectangle visual = getVisualRectangle();`. Масштаб берётся через `mapCamera->getZoomLevel()`, `visualScale` — точным вызовом `unitWorldScaleFactor` из задания. Каждый из трёх вызовов функции получает `pixelW` и `density` собственной текстуры. Корпус и тень используют `bmp_body`, башня — `bmp_head`; строка у всех — `iFrame`.

   Только в ветке тени керриола к полученному `dest.y` прибавляется литерал `24`. Сохраняются ранние выходы, проверки указателей, лог отсутствующего корпуса, `ShadowTrans`, условие башни, порядок тень → корпус → башня, координаты `SYMB_PICKMEUP` и рамка `FOCUS`.

4. Отдельная программа `UnitFrameLayoutTests.cpp` проверяет целиком `src` и `dest` для У1–У10: все заданные столбцы, строки, варианты Н1/Н2, сетку масштабов, старый и неверный атласы, неполные HD-поля и прямоугольный кадр. Ожидания записываются литералами; смещения источника в циклах — литералом размера кадра, умноженным на индекс. Провал печатается как `FAIL` с номером случая, входом, результатом и ожиданием. Цель CMake — `unit_frame_layout_tests`, имя CTest — `unit_frame_layout`.

5. Генератор читает новые поля и различает три состояния: оба отсутствуют или равны нулю; оба заданы положительными; ошибочное сочетание. Ошибка состояния содержит имя типа. `resolve_frame_hd4` сохраняет обычный кадр для типов без HD-полей, принимает единую положительную HD-пару при допустимой ширине атласа, отвергает смесь состояний, разные пары и неверную ширину с именем атласа. Неоднозначность классических размеров продолжает давать прежнюю ошибку.

6. Пять записей Осадного получают ссылки на два конкретных присваивания HD-полей; ссылки на обнуление не добавляются. `draw_rules` описывает условие и обе ветви новой функции, ссылается на заголовок и три вызова. Смещение керриола читается из нового текста ветки. Ссылка старого `start_y` во всех затронутых записях заменяется единым фрагментом строки вызова, содержащим `iFrame`; текст значения `row_meaning` сохраняется. Все идентификаторы должны находиться на указанных строках.

7. В существующих тестах контракта меняются только разрешённые ожидания: исключение пяти записей Осадного из общего правила ×4 и новые размеры `UNIT_SIEGEBASE`. Добавляются проверка пяти классических/HD-кадров и отдельный класс Т1–Т6 без `skipUnless`. Модуль импортируется через `sys.path` из `tools/units3d`; обращение к отсутствующей функции происходит внутри тестов, чтобы красный прогон сохранил остальные проверки.
