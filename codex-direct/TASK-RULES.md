## Среда servak

- Рабочая копия задания — папка, из которой тебя запустили (`/srv/dune/worktrees/<id>`). Писать можно только в неё.
- Исключение из правил «в корень рабочей копии ничего временного не класть» и «всё, что создаёшь вне рабочей копии, — в папку задачи»: папка задачи — `<рабочая копия>/.tmp/<id задачи>/`. Временные файлы, одноразовые скрипты и выгрузки — только в неё. Папка `.tmp/` исключена из git через `.git/info/exclude`. Системный `/tmp` не используй.
- Файлы Git LFS в рабочих копиях `/srv/dune/worktrees/u*` — настоящие данные. В остальных рабочих копиях это текстовые указатели, а настоящие паки лежат вне репозитория, только для чтения: `/srv/dune/inputs/packs/` (`sdl_data.dat`, `sdl_data_hd4.dat`).
- Python с Pillow, numpy и scipy (pytest нет, тесты — `unittest`): `/srv/dune/venv/bin/python`. Blender 5.2.3 LTS: `/srv/dune/tools/blender-5.2.3-linux-x64/blender` (запускать с `-b --factory-startup`). Видеокарт нет: рендер только на CPU.
- Сети нет. Ничего не устанавливать и не скачивать. Нужна сеть или пакет — `Q` и стоп.

## Git

- Работаешь в ветке `codex/<id>` своей рабочей копии.
- Исключение из правил о коммитах: коммитов не делаешь. Песочница Codex на servak держит служебную папку git только для чтения. Коммиты делает ведущий по списку из сдачи: на каждый законченный подпункт — сообщение и файлы по именам. Команды `git add`, `commit`, `push`, `rebase`, `reset --hard`, `clean`, `stash` и любые `gh` запрещены. Вместо `git diff --cached` список коммита проверяй командами `git status --short` и `git diff --stat`.
- В список коммита — только свои файлы по именам. Временное, `.tmp/` и машинные пути в коммит не попадают.

## Комментарии в коде

Категорически запрещено писать комментарий по принципу «полезен, если верен и относится к делу». По умолчанию комментария нет; он должен доказать право на существование: только неочевидное «почему» — инвариант, причина обхода, ссылка на внешнее ограничение. Пересказ кода, планы и история — нет. Внутренние номера находок, планов и решений (`F7`, `A-11b`, `D88`) в комментарий не писать: суть словами. Субагентам и исполнителям этот абзац передавать в бриф дословно.

## План, разведка, вопросы

- План пишет ведущий. Ты планов не пишешь и не одобряешь, внутренние планы помощников тоже не одобряешь.
- Если задание требует разведку, первая сдача — блок `## RECON-<id>` и стоп. В нём: что прочитано из раздела «Прочитать до работы» и чего в задании не хватило; факты с `файл:строка`; команды и их выводы; таблицы, которых требует задание. Развилок, предложений, рекомендаций, плана и правок в разведке нет.
- Получив блок `## PLAN-<id>` ведущего, выполняй его дословно и в его порядке. Конфликт плана с кодом, нормой или данными — `Q` и стоп.
- Вопросы этапа — одним блоком `## Q-<id>-NN` (NN — номер блока по порядку) и стоп.
