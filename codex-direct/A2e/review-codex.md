### Находка

**Переполнение `int64` нарушает точное сравнение с дробным порогом.**

- **Файл:** [render_unit.py:260](/srv/dune/worktrees/a2e-r/tools/units3d/render_unit.py:260), тип операндов задаётся на [строке 250](/srv/dune/worktrees/a2e-r/tools/units3d/render_unit.py:250).
- **Что не так:** знаменатель `Fraction` умножается на массив `numpy.int64`. Для допустимого `min_saturation = 0.18000000000000002` знаменатель равен `50000000000000000`. Произведение на 255 равно `12750000000000000000`, что превышает максимум `int64` — `9223372036854775807`.
- **Воспроизведение:** правило `hue_deg=0`, `hue_width_deg=25`, `min_saturation=0.18000000000000002`, `min_value=0.14`; тексель `(255,0,0)`. Точный расчёт включает тексель в краску, `paint_texels` исключает. Рендер подтвердил **α = 0 вместо 255**.
- **Спецификация:** §2, строгие неравенства `house_paint`; §4, покрытие маски по доле краски.
- **Последствие:** допустимый порог может исключать полностью насыщенную краску и менять зону перекраски в игре. Проверка происхождения такой ошибки не обнаружит.
- **Блокирует:** да, соответствие классификации спецификации. Текущие короткие пороги пилота этого переполнения не вызывают.
- **Причина:** код.
- **Предложенная правка:** выполнять дробные сравнения без переполнения — использовать целые произвольной точности либо заранее вычислять точные пороги для диапазона каналов 0–255.

Доказательства: [числовой оракул](/srv/dune/worktrees/a2e-r/.tmp/review3-numeric.log), [проба рендера](/srv/dune/worktrees/a2e-r/.tmp/review3-render-probe.log).
