# Задание A2e-R — независимое ревью кода конвейера рендера юнитов

Режим: ревью без правок. Плана не нужно: сдача — одним последним сообщением `## REVIEW-A2e-R`. Исполнитель: Codex `gpt-6.1-sol` `high`; механика — субагентам `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/a2e-r`, ветка `units3d/pilot`, коммит `16371009`.

## Цель

Конвейер рендера юнитов написал ведущий Claude. Нужна независимая проверка другой семьёй моделей: найти, где код расходится со спецификацией и где атлас окажется неверным, хотя `check_unit.py` даёт `PASS`.

Проверяются три файла:
- `tools/units3d/render_unit.py` — команда 1;
- `tools/units3d/build_atlases.py` — команда 2;
- `tools/units3d/install.py` — команда 3.

Источник истины — `docs/units/UNITS3D_SPEC.md`, разделы 1–6. Если код и спецификация расходятся, находка — расхождение; какая сторона права, пишет ведущий.

Облик не оценивай: цвет, материал и читаемость судят ведущий и владелец. Твоя работа — код, числа и файлы.

## Что сделать

1. **Прочитать** три файла целиком и разделы 1–6 спецификации. Ищи:
   - расхождения со спецификацией: формулы раздела 1, состав и формат выхода раздела 4, правила установки команды 3;
   - места, где выход зависит от машины: переводы строк в файлах, хэши которых пишутся в манифест; пути; порядок обхода; случайность без `seed`;
   - порчу пака: изменение записей не из `parts`, их порядка, имён или расширений;
   - ошибки, которые проходят проверки 1–10 `check_unit.py`, но дают неверный атлас в игре.
2. **Прогнать команды 1–4** для обоих юнитов пилота (`siegebase`, `devastator`) в `.tmp/`. Порядок подготовки:
   - скопируй `resources/hd/units3d/` в `.tmp/units3d/`;
   - в копии замени указатели Git LFS моделей настоящими файлами из `/srv/dune/inputs/glb/`:
     - `desert_tank.glb` → `.tmp/units3d/siegebase/source/desert_tank.glb`;
     - `red_tank.glb` → `.tmp/units3d/devastator/source/red_tank.glb`;
   - проверь, что SHA-256 моделей совпадают с объектами репозитория: `desert_tank.glb` — `dae691edee77fd96b52ddb1dc325410e79aa1d57ab25b9d5acb2f28cc809efd9`, `red_tank.glb` — `72d9ec779971d3f266a33941a5ebb5775db5d3b686740efed1a3bba76a025e91`;
   - пак «до» — `/srv/dune/inputs/packs/sdl_data_hd4.dat` (только чтение); пак «после» — его копия `.tmp/pack-<юнит>.dat`, в которую ставит команда 3.

   Команды — из раздела 3 спецификации; `--unit` указывает на `.tmp/units3d/<юнит>`. Blender: `/srv/dune/tools/blender-5.2.3-linux-x64/blender -b --factory-startup`. Python: `/srv/dune/venv/bin/python`. Проверка (команда 4) — с `--pack-before` и `--pack-after`, без `--allow-skip`. Сохрани полный вывод `check_unit.py` каждого юнита.
3. **Повторяемость.** Повтори команды 1–2 для обоих юнитов в другие папки. Сравни скриптом каждый атлас первого и второго прогона:
   - доля пикселей, совпадающих во всех четырёх каналах;
   - максимальная разница канала.

   Порог проверки 11 спецификации: ≥ 99,9 % пикселей совпадают, разница канала ≤ 2.

## Сдача

Последнее сообщение — `## REVIEW-A2e-R | время | коммит 16371009`. В нём:
- **Вердикт:** `ACCEPT` или `REJECT`.
- **Находки.** По каждой:
  - файл:строка;
  - что не так;
  - пункт спецификации;
  - последствие в игре или в проверке;
  - блокирует или нет;
  - причина: код, спецификация или среда;
  - предложенная правка.
- **Вывод `check_unit.py`** обоих юнитов — 10 строк каждого и код выхода.
- **Таблица повторяемости:** атлас → доля совпадающих пикселей → максимальная разница канала.
- **Не проверено** — раздел обязателен.

Отчётных файлов не заводить, кроме логов в `.tmp/`.

## Не трогать

Все файлы под git. Писать можно только в `.tmp/`.

## Организация работы

- Порядок: чтение файлов и прогоны команд 1–4 идут одновременно → повторный прогон команд 1–2 → сравнение атласов → сверка находок с прогонами → `REVIEW-A2e-R`.
- Параллельно: прогоны двух юнитов независимы, чтение кода от прогонов не зависит — всё это запускай сразу.
- Помощники: `gpt-6-luna` `xhigh`, независимые части — сразу, до 3 одновременно: прогоны команд по юнитам, скрипт сравнения атласов, выжимки логов. Чтение кода, находки и вердикт — твои.
- Остановки: если команда падает из-за среды, а не кода (нет файла вне репозитория, нет прав), — `Q` с логом и стоп. Сдача — `REVIEW-A2e-R` после сравнения атласов.
- Рамка правок: только `.tmp/`; правка вне рамки запрещена.
- Журнал: `.tmp/progress.md`, строка после каждого закрытого шага порядка.
