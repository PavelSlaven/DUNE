## Неверные реализации

Каждый тест из таблицы обязан падать хотя бы на одной из них; каждая из них обязана ронять хотя бы один тест. Проверь это сам: копия `tools/` во временной папке `.tmp/mutants/<имя>/`, одна правка, прогон тестов против копии. В рабочих файлах инструмента ничего не меняй.

1. `fit` возвращает найденное значение − 0,05.
2. Поиск `fit` не учитывает обрезку перекраски (проверка перекраски внутри поиска выключена).
3. Числовой `scale` записывается в `params.json`, а кадры ставятся по медиане.
4. Доля маски считается по маске до дополнения `red_fill`.
5. Поле `figures` не читается: сохраняется одна наибольшая область.
6. Нижняя граница `fit` — 0,5, а не 0,8 · медиана.
7. Текущий инструмент (ветка `codex/u10` до R10): на нём тесты 26, 27, 28 падают, а 21, 21b, 22, 24 проходят — они проверяют поведение, которое уже верно.

## Чем проверить

- Прогон каждого нового и изменённого теста на текущем инструменте: какие падают и почему — строки вывода в сдачу.
- Прогон каждого мутанта: какие тесты падают — таблица «мутант → упавшие тесты» в сдачу.
- `sha256sum` нового `test_redraw.py` — строка для `ACCEPTANCE.sha256` (файл `ACCEPTANCE.sha256` обнови сам).

## Организация работы

- Порядок: PLAN → `PLAN-OK-U1-T2` → тесты → прогоны на текущем инструменте → мутанты → строка `ACCEPTANCE.sha256` → сдача `## DONE-U1-T2`.
- Параллельно: тесты 21, 21b, 22, 24 и тесты 26, 27, 28 пишутся независимо; прогоны мутантов независимы друг от друга.
- Помощники: два субагента `gpt-6-luna` `xhigh` пишут эти две группы тестов сразу; после сведения — субагенты прогоняют мутанты, по 4 одновременно, пока мутанты не кончатся. Сам — PLAN, сведение в один файл, итоговая сверка с заданием.
- Остановки — блок `## Q-U1-T2-NN` и стоп: требование таблицы спорит с заданием `TASK.md`; тест нельзя написать без внутренних функций инструмента; множитель теста 21 с `fit` строго между 0,8 · медиана и медианой не находится.
- Рамка правок: `tools/units3d/tests/test_redraw.py`, `tools/units3d/tests/ACCEPTANCE.sha256`, `.tmp/`.
- Журнал: `.tmp/progress.md`, строка после каждого шага порядка.
- Коммитов не делай; раздел `### Коммиты` в сдаче: сообщение `Strengthen fit, scale and red fill acceptance tests; add multi-figure tests` и список двух файлов.
- Комментарии в коде. Категорически запрещено писать комментарий по принципу «полезен, если верен и относится к делу». По умолчанию комментария нет; он должен доказать право на существование: только неочевидное «почему» — инвариант, причина обхода, ссылка на внешнее ограничение. Пересказ кода, планы и история — нет. Внутренние номера находок, планов и решений (`F7`, `A-11b`, `D88`) в комментарий не писать: суть словами.
