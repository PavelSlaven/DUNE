# Задание U1 — инструмент перерисовки юнитов под 63° на примере Девастатора

Режим: **«План у ревьюера»** (см. «Режимы задания» в конце). Исполнитель: Codex `gpt-6.1-sol` `high`; механика — субагентам `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/u1`, ветка `codex/u1` от `units63/main`. План работ: `docs/units/REDRAW_PLAN.md`, фаза U1.

## Цель

Постоянный инструмент `tools/units3d/redraw.py` повторяет конвейер G3: делает входы генерации и перекраски, считает метрики попыток и правило тени старого пака, собирает из исходников юнита кадры, маску Дома, тень и атласы с проверками, заменяет записи юнита в копии пака со сверкой остальных записей и рисует листы. Девастатор собирается инструментом из файлов репозитория пиксель в пиксель как принятые атласы `codex-direct/G3/atlas/`, и приёмочные тесты `tools/units3d/tests/test_redraw.py` проходят.

## Зачем

Девастатор, перерисованный под камеру 63°, принят владельцем в игре. Его собрали разовые скрипты `codex-direct/G3/scripts/`. Дальше тем же способом перерисовываются ещё 17 юнитов, поэтому способ становится одним инструментом, который параметризован описанием юнита и проверен тестами.

## Термины

- **Кадр** — клетка атласа юнита: ряд `row` (кадр анимации) и направление `k` (0…7 — восток, северо-восток, север, северо-запад, запад, юго-запад, юг, юго-восток). Клетка `(row, k)` занимает в атласе прямоугольник `x = k·FW … k·FW + FW`, `y = row·FH … row·FH + FH`, где `FW × FH` — размер кадра юнита.
- **M** = `max(FW, FH)`. Холст генерации — 1024 × 1024; один пиксель старого кадра равен `1024 / M` пикселей холста. В скриптах G3 вместо `M` стоит `FH` (у Девастатора `FH > FW`, поэтому для него формулы совпадают).
- **Непрозрачный пиксель** — пиксель с альфой больше 127.
- **Рамка** — наименьший прямоугольник, содержащий все непрозрачные пиксели (функция `bbox` в `common.py`).
- **Старый пак** — пак репозитория `resources/bin/data/sdl_data_hd4.dat` до замены записей.

## Описание юнита — `unit.json`

Папка юнита — `tools/units3d/units/<имя атласа тела>/`, в ней `unit.json`. Пути внутри — от корня репозитория. Формат (значения — для Девастатора; создай этот файл с ними):

```json
{
  "atlases": {"body": "UNIT_DEVASTATOR", "house_mask": "HM_UNIT_DEVASTATOR", "shadow": "UNIT_DEVASTATOR_SHADOW"},
  "frame": [152, 184],
  "rows": 1,
  "block": [115.0, 88.0, 48.0],
  "height_estimate": 49.0,
  "shadow_rule": {"shift": 4, "alpha": 46, "rgb": [5, 4, 3]},
  "sheet_building": {"name": "BUILD_HEAVYFACTORY", "size": [384, 256]},
  "frames": [
    {"row": 0, "k": 0, "attempts": {"a": "codex-direct/G3/out/g3_k0_a.png", "b": "codex-direct/G3/out/g3_k0_b.png"}, "pick": "b", "recolour": "codex-direct/G3/out/g3b_k0.png"}
  ]
}
```

- `frames` содержит по одной записи на каждый кадр `(row, k)` атласа: у Девастатора — восемь записей, `row` 0, `k` 0…7, с путями и выбором из «Источника истины».
- `house_mask: null` — у юнита нет маски Дома: перекраска, IoU и доля маски не считаются, поле `recolour` отсутствует. `shadow: null` — у юнита нет тени: атлас тени не строится, поле `shadow_rule` отсутствует.
- `block` — длина, ширина и высота бруска-ориентира в пикселях старого кадра; `height_estimate` — высота юнита в пикселях старого кадра для расчёта пропорций в `score` (в G3 — `H = 49`).
- Размер атласа берётся из старого пака (размер картинки записи `atlases.body`), а не вычисляется: у Девастатора атлас 1216 × 192 при кадре 152 × 184. Пиксели атласа вне клеток кадров — прозрачные нули, как в G3.
- Поле `frames[].attempts` может быть пустым словарём `{}`, а `pick` — отсутствовать, пока попытки не сгенерированы: такой юнит годится для команды `inputs`, а остальные команды отказывают с кодом 2 и сообщением, какого поля нет.

## Команды

Вызов: `/srv/dune/venv/bin/python tools/units3d/redraw.py <команда> <папка юнита> [аргументы]` из корня репозитория. Параметр `--pack <путь>` у каждой команды задаёт старый пак; по умолчанию — пак репозитория. Код выхода: 0 — успех; 1 — проверка не прошла; 2 — неверный вход.

### `inputs <папка юнита> <выход>`

Для каждого кадра — два файла RGB 1024 × 1024, как `make_inputs.py`, с `M` вместо `FH`:
- `old_r<row>k<k>.png` — кадр `(row, k)` атласа тела из старого пака, уменьшенный методом LANCZOS до `(round(FW·1024/M), round(FH·1024/M))` и наложенный на пурпурный (255, 0, 255) холст в точку `((1024 − ширина) // 2, (1024 − высота) // 2)`;
- `guide_r<row>k<k>.png` — брусок-ориентир направления `k`, отрисованный Blender на прозрачном фоне и наложенный на пурпурный холст в точку (0, 0).

Брусок рисует `tools/units3d/guide_blender.py` — перенос `guide.py` G3, где длина, ширина и высота бруска берутся из `block`, а `ortho_scale` камеры равен `M`. Blender: `/srv/dune/tools/blender-5.2.3-linux-x64/blender -b --factory-startup --python tools/units3d/guide_blender.py -- …`. Путь к Blender задаётся переменной окружения `BLENDER`, по умолчанию — этот путь.

### `recolour-inputs <папка юнита> <выход>`

Только при `house_mask` не `null`. Для каждого кадра:
- `pick_r<row>k<k>.png` — выбранная попытка `attempts[pick]`, приведённая к 1024 × 1024 методом LANCZOS, с вырезанным фоном (`key` из `common.py`) и заново наложенная на пурпурный, как в `frames.py` (`flat`);
- `oldmask_r<row>k<k>.png` — то же, что `old_r<row>k<k>.png` из `inputs`, но в кадре старого атласа тела до уменьшения пиксели, где у кадра старого атласа маски альфа больше 127, получают цвет (0, 255, 0) с прежней альфой.

### `score <папка юнита> [--out <файл>]`

Только чтение. Для каждого ряда — вывод `ratios.py` и `choose.py` G3 с `M` вместо `FH` и `height_estimate` вместо `H`: по каждой попытке ширина и высота рамки после вырезки фона, отношение высоты к ширине, расчётное отношение для 63°, ошибка ракурса, отношение ширины к старой; IoU зеркальных пар (0, 4), (1, 3), (5, 7) для старых кадров и для всех сочетаний попыток; по три лучших набора выбора по разбросу ширины, по IoU зеркальных пар и по ошибке ракурса. Текст — в stdout и, при `--out`, в файл. Выбор попыток делает ведущий; команда ничего не выбирает и `unit.json` не меняет.

### `shadow-rule <папка юнита>`

Только при `shadow` не `null`. По старому паку: для каждого сдвига `s` от 0 до 8 включительно альфа тела сдвигается на `s` пикселей вправо и вниз (`b[s:, s:] = alpha[:H−s, :W−s]` по всему атласу); прозрачность `a` = медиана альфы старой тени по пикселям, где сдвинутая альфа тела больше 0 и альфа старой тени больше 0; прогноз = сдвинутая альфа тела × `a` / 255; корреляция — коэффициент Пирсона прогноза и альфы старой тени по всем пикселям атласа. Берётся сдвиг с наибольшей корреляцией. Цвет — поканальная медиана RGB старой тени по пикселям с альфой больше 0. Печатает одну строку JSON `{"shift": s, "alpha": round(a), "rgb": [r, g, b], "corr": c}` (rgb — целые после `round`, `corr` — с тремя знаками). Код 1, если корреляция меньше 0,95. `unit.json` команда не меняет.

### `build <папка юнита> <выход>`

Повторяет `frames.py` и `atlas.py` G3 для всех кадров юнита, с `M` вместо `FH`:
1. Каждая выбранная попытка `attempts[pick]` приводится к 1024 × 1024 методом LANCZOS, фон вырезается функцией `key` из `common.py` (пурпурный фон; если все четыре угловых пикселя темнее 16 — чёрный фон, связанный с краем картинки).
2. Масштаб `scale` — медиана по всем кадрам юнита отношения «ширина рамки старого кадра / (ширина рамки после вырезки × M / 1024)».
3. Кадр ставится функцией `place` из `common.py` (холст уменьшается до `round(M·scale)`): центр рамки — в центр рамки старого кадра, при выходе непрозрачной или полупрозрачной части за край кадра — сдвиг внутрь. Если и после сдвига часть юнита выходит за кадр (`clipped`), кадр не проходит.
4. При `house_mask` не `null`: перекраска `recolour` приводится к 1024 × 1024 методом LANCZOS и ставится с тем же сдвигом, что и кадр; IoU непрозрачных пикселей кадра и перекраски должна быть не меньше 0,97. Маска — пиксели перекраски с `G − max(R, B) ≥ 80` на 1024-холсте, поставленные с тем же масштабом и сдвигом; цвет маски белый, альфа маски умножается на альфу тела и делится на 255 с округлением, как в `atlas.py`. Доля маски кадра = число непрозрачных пикселей маски / число непрозрачных пикселей тела. Коридор доли — от (наименьшая доля старой маски по кадрам юнита − 0,05) до (наибольшая доля старой маски по кадрам юнита + 0,05), где доля старой маски кадра = непрозрачные пиксели кадра старого атласа маски / непрозрачные пиксели кадра старого атласа тела. Доля вне коридора — кадр не проходит.
5. При `shadow` не `null`: тень кадра — цвет `shadow_rule.rgb`, альфа = альфа тела, сдвинутая на `shadow_rule.shift` вправо и вниз, × `shadow_rule.alpha` / 255 с округлением, как в `atlas.py`.
6. Атласы размера старого атласа тела; запись в PNG — `encode_png` из `tools/hd_assets.py`.

Выход: `frames/r<row>k<k>.png` (кадры тела); `params.json` — `scale`, сдвиг каждого кадра и признак сдвига внутрь; `metrics.txt` — строка на кадр: `row`, `k`, `pick`, IoU, доля маски, доля старой маски (три знака после запятой), `ok`, и итоговая строка с коридором и списком непрошедших кадров. Если все кадры прошли — ещё атласы `<имя>.png` и `atlases.json` в формате `codex-direct/G3/atlas/atlases.json` (`entries` → имя → `file`, `sha256`, `size`), код 0. Если хоть один кадр не прошёл — атласы и `atlases.json` не пишутся, в stderr — список непрошедших кадров с причиной (`iou`, `share`, `clipped`), код 1.

### `pack <папка атласов> <копия пака> [--source <пак>]`

Как `pack.py` G3: копирует исходный пак (по умолчанию — пак репозитория) в `<копия пака>`, заменяет записи из `atlases.json` через `tools/units3d/install.py` и сверяет: список записей (индекс, имя, расширение) не изменился; изменились ровно записи из `atlases.json`; их содержимое байт в байт равно файлам атласов. Печатает число записей, число неизменных и список заменённых. Любое расхождение — код 1. Пак репозитория команда не меняет.

### `contact <папка юнита> <папка входов> <выход.png>` и `sheet <папка юнита> <папка атласов> <выход.png> [--row N]`

- `contact` — как `contact.py` G3: по строке на кадр — старый кадр и брусок из папки входов (`old_r…`, `guide_r…`) и все попытки из `attempts`, клетки 300 × 300 с подписями.
- `sheet` — как `sheet.py` G3 для ряда `N` (по умолчанию 0): старый и новый юнит в цветах трёх Домов с тенью, ×2, и внизу оба рядом со зданием `sheet_building` в масштабе игры. Имена атласов — из `unit.json`; без маски Дома юнит рисуется без окраски, без тени — без тени.

## Организация работы

- Порядок: PLAN → `PLAN-OK-U1` → `unit.json` Девастатора и общие функции → команды `build` и `pack` → `inputs`, `recolour-inputs`, `guide_blender.py` → `score`, `shadow-rule` → `contact`, `sheet` → полный прогон тестов и ручной прогон → DONE.
- Параллельно: после общих функций команды `inputs` с `guide_blender.py`, `score`, `shadow-rule`, `contact` и `sheet` независимы друг от друга и от `build`.
- Помощники: субагенты `gpt-6-luna` `xhigh` пишут и проверяют эти команды сразу, по 4 одновременно, пока команды не кончатся; сам — PLAN, общие функции, `build`, итоговая сверка.
- Остановки — блок `## Q-U1-NN` и стоп:
  - приёмочный тест краснеет, а ты считаешь тест неверным;
  - атласы Девастатора не совпадают с эталоном пиксель в пиксель после двух разных исправлений;
  - для команды нужен файл или пакет, которого нет в рабочей копии и в `/srv/dune/venv`.
- Рамка правок: `tools/units3d/redraw.py`, `tools/units3d/guide_blender.py`, `tools/units3d/units/`, `tools/units3d/tests/test_redraw_unit.py`, `.tmp/`.
- Журнал: `.tmp/progress.md`, строка на законченный шаг порядка.
- Надзор ведущего: через 45 минут после старта, затем каждые 30 минут — по `.tmp/progress.md`.
