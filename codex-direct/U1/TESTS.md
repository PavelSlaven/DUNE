# Задание U1-T — приёмочные тесты инструмента перерисовки до реализации

Режим: **«План у ревьюера»** (см. «Режимы задания» в конце). Исполнитель: Codex `gpt-6.1-sol` `high`; механика — субагентам `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/u1`, ветка `codex/u1`. Инструмента `tools/units3d/redraw.py` ещё нет: его напишет другая нить по заданию `codex-direct/U1/TASK.md` после тебя.

## Цель

Приёмочные тесты `tools/units3d/tests/test_redraw.py` проверяют поведение инструмента, описанное в `codex-direct/U1/TASK.md`, только через его командную строку; на пустой реализации каждый тест краснеет по заявленной причине; файл заморожен строкой SHA-256 в `tools/units3d/tests/ACCEPTANCE.sha256`.

## Источник истины

- Поведение инструмента — `codex-direct/U1/TASK.md`, разделы «Термины», «Описание юнита — `unit.json`», «Команды» (форматы вывода `metrics.txt`, `params.json`, stderr `build`, JSON `shadow-rule` и текст `score` заданы там). Тест проверяет только то, что там написано.
- Эталоны — таблица «Источник истины» в `codex-direct/U1/TASK.md`: атласы `codex-direct/G3/atlas/`, метрики `codex-direct/G3/metrics.txt`, выбор и вывод метрик `codex-direct/G3/choice.txt`, входы `codex-direct/G3/input/` и `codex-direct/G2/input/`.
- Стиль тестов — соседние `tools/units3d/tests/test_check_unit.py` и `test_unit_contract.py`: модуль `unittest`, запуск из корня репозитория.

## Что сделать

Создай `tools/units3d/tests/test_redraw.py`. Тесты вызывают инструмент только как процесс: `[sys.executable, 'tools/units3d/redraw.py', <команда>, …]` из корня репозитория, и читают его выходные файлы, stdout, stderr и код выхода. Внутренние функции инструмента тесты не импортируют. Описание Девастатора тесты берут из `tools/units3d/units/UNIT_DEVASTATOR/unit.json`; для случаев с изменённым описанием тест копирует его во временную папку, меняет нужное поле и подаёт копию. Все выходы — во временных папках (`tempfile.TemporaryDirectory`).

## Чем проверить

- `/srv/dune/venv/bin/python -m unittest tools.units3d.tests.test_redraw -v` из корня репозитория на пустой реализации: каждый из 20 тестов краснеет, причина — отсутствие инструмента или его выхода, а не ошибка самого теста. Вывод — в сдачу.
- Ошибки в коде самих тестов (опечатки, неверные пути к эталонам) ловит прогон проверочной заглушки: временный файл `.tmp/stub/redraw.py`, который для случаев 1, 2, 10–14 копирует или строит эталонный выход прямо из эталонных файлов. Подставь заглушку на время прогона копией в `tools/units3d/redraw.py`, прогони, удали копию; случаи 1, 2, 10–14 должны пройти. Заглушку в коммит не клади.
- `sha256sum -c tools/units3d/tests/ACCEPTANCE.sha256` — ОК.

## Организация работы

- Порядок: PLAN → `PLAN-OK-U1-T` → тесты 1–20 → прогон на пустой реализации → прогон с заглушкой → строка в `ACCEPTANCE.sha256` → коммит → DONE.
- Параллельно: группы тестов 1–3 с 15–18, 4–9 с 20, 10–11 и 12–14 с 19 независимы друг от друга.
- Помощники: субагенты `gpt-6-luna` `xhigh` пишут эти четыре группы тестов сразу, по 4 одновременно; сам — PLAN, сведение в один файл, прогоны и итоговая сверка с заданием.
- Остановки — блок `## Q-U1-T-NN` и стоп: требование таблицы спорит с заданием `codex-direct/U1/TASK.md`; тест нельзя написать без внутренних функций инструмента; эталонный файл не читается.
- Рамка правок: `tools/units3d/tests/test_redraw.py`, `tools/units3d/tests/ACCEPTANCE.sha256`, `.tmp/`.
- Журнал: `.tmp/progress.md`, строка после каждого шага порядка.
- Коммит: один, `Add acceptance tests for the unit redraw tool`, только два файла рамки.
