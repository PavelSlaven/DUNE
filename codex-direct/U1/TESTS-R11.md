# Задание U1-T3 — приёмочные тесты доработки R11: сдвиг кадра от другого ряда и коды выхода `pack`

Режим: **«План у ревьюера»** (см. «Режимы задания» в конце). Исполнитель: Codex `gpt-6.1-sol` `high`; помощники — субагенты `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/u1`, ветка `codex/u11`. Коммитов не делай: ведущий коммитит по списку из сдачи.

## Цель

Приёмочные тесты в `tools/units3d/tests/test_redraw.py`, которые падают на текущем инструменте и на каждой неверной реализации из раздела «Неверные реализации», а на верной реализации R11 по заданию `codex-direct/U1/TASK.md` проходят.

## Источник истины

- Задание `codex-direct/U1/TASK.md` в ветке `codex/u11`: в разделе «Описание юнита» пункт о поле `offset_from`; раздел `build`, шаги 2 и 3 (медиана без кадров с `offset_from`, постановка кадра со сдвигом кадра `(R, k)`, поиск `"fit"`), описание `params.json`; раздел `pack`, абзац «Коды выхода `pack`».
- Стиль и помощники тестов — существующий `tools/units3d/tests/test_redraw.py` (`copy_unit`, `save_unit`, `run_tool`, `_troopers_unit` и его способ строить идеальные входы из старых кадров).
- Старые кадры — закреплённый исходный пак `tools/units3d/data/sdl_data_hd4_source.dat` (константа `SOURCE_PACK`), чтение — через `tools/hd_assets.py` (`read_pack`, `decode_image`).

## Что сделать

Тесты вызывают только командную строку `tools/units3d/redraw.py` и читают её выходные файлы; внутренние функции инструмента не вызывают.

**Юнит теста — Харвестер.** Описание `UNIT_HARVESTER`: атласы `{"body": "UNIT_HARVESTER", "house_mask": null, "shadow": null}`, кадр 320 × 208, `rows` 2, записи `(0, k)` и `(1, k)` для k = 0…7. Попытка записи `(0, k)` — старый кадр ряда 0, поставленный на пурпурный холст 1024 × 1024 так, как задание описывает вход `old_r…` команды `inputs` (как в `_troopers_unit`). Попытка записи `(1, k)` — та же картинка, что у `(0, k)`, и к ней добавлена **полоса**: сплошной прямоугольник RGB (128, 128, 128), примыкающий к рамке тела на холсте слева вплотную, высотой 50 % высоты рамки, по вертикали — по середине рамки, шириной W; W — доля ширины рамки, одна на все k, её подбираешь ты (ниже). У записей `(1, k)` — поле `"offset_from": 0`. Полоса — деталь, которая меняет рамку кадра, как песчаный шлейф.

## Неверные реализации

Каждый тест из таблицы обязан падать хотя бы на одной из них; каждая из них обязана ронять хотя бы один тест. Проверь это сам: копия `tools/` во временной папке `.tmp/mutants/<имя>/`, одна правка, прогон тестов против копии. В рабочих файлах инструмента ничего не меняй.

Основа мутантов 1–5 — верная реализация R11, которой в ветке нет. Поэтому: прогон текущего инструмента (мутант 6) обязателен и должен ронять тесты 29–33; для мутантов 1–5 сдай таблицу «мутант → тесты, которые обязаны упасть, и почему» по тексту тестов, без прогона, и пометь её в сдаче как непроверенную прогоном.

1. Поле `offset_from` не читается: кадр центрируется и сдвигается внутрь, как любой другой.
2. Медиана масштаба считается по всем кадрам, включая кадры с `offset_from`.
3. Кадр с `offset_from` после постановки со сдвигом кадра `(R, k)` ещё сдвигается внутрь при выходе за край.
4. Поиск `"fit"` проверяет обрезку кадров с `offset_from` с их собственным центрированием, а итоговая постановка — со сдвигом кадра `(R, k)`.
5. `pack` перехватывает `ValueError`, `KeyError` и `TypeError` и возвращает код 1.
6. Текущий инструмент ветки `codex/u11` до R11.

## Чем проверить

- Подбор W теста 31: масштабы и строки `metrics.txt` двух сборок при выбранном W — в сдачу.

## Организация работы

- Порядок: PLAN → `PLAN-OK-U1-T3` → тесты → прогоны на текущем инструменте → таблица мутантов 1–5 → строка `ACCEPTANCE.sha256` → сдача `## DONE-U1-T3`.
- Параллельно: тесты 29–32 (юнит теста) и тест 33 (`pack`) пишутся независимо.
- Помощники: два субагента `gpt-6-luna` `xhigh` пишут эти две группы тестов сразу; прогоны и выжимки логов — субагенту. Сам — PLAN, подбор W, сведение в один файл, таблица мутантов, итоговая сверка с заданием.
- Остановки — блок `## Q-U1-T3-NN` и стоп: требование таблицы спорит с заданием `TASK.md`; тест нельзя написать без внутренних функций инструмента; W теста 31 с обоими условиями не находится.
- Рамка правок: `tools/units3d/tests/test_redraw.py`, `tools/units3d/tests/ACCEPTANCE.sha256`, `.tmp/`.
- Журнал: `.tmp/progress.md`, строка после каждого шага порядка.
- Коммитов не делай; раздел `### Коммиты` в сдаче: сообщение `Add acceptance tests for row offsets and pack exit codes` и список двух файлов.
- Комментарии в коде. Категорически запрещено писать комментарий по принципу «полезен, если верен и относится к делу». По умолчанию комментария нет; он должен доказать право на существование: только неочевидное «почему» — инвариант, причина обхода, ссылка на внешнее ограничение. Пересказ кода, планы и история — нет. Внутренние номера находок, планов и решений (`F7`, `A-11b`, `D88`) в комментарий не писать: суть словами.
