### Входы, режимы и выходы `reference_shots.py`

Инструмент принимает обязательные `--out` и `--new-dir`. Для сравнения со старой сборкой нужно указать ровно один из вариантов: `--old-dir` со старым исполняемым файлом и ресурсами, `--old-png-dir` с готовыми PNG старых сцен или `--no-old`, чтобы обработать только новую сборку. Для данных есть `--pairs` и `--gallery-file`; по умолчанию это `reference_pairs.tsv` и `reference_gallery.tsv` рядом с инструментом. Также предусмотрены `--language` (`ru` или `en`, по умолчанию `ru`), `--headless`, повторяемый `--only` для отбора пар и флаг `--gallery`. В режиме галереи аргументы старой сборки и `--only` не используются. Название исполняемого файла выбирается по платформе: `d2tm.exe` для Windows, иначе `d2tm`.

Файл пар содержит заголовок `pair, fork_scene, port_scene, resolutions, note` и 27 записей. Файл галереи содержит `file, port_scene, resolution` и пять записей. Инструмент также получает на вход каталоги сцен из `--ui-audit-list`; для сцен запускает сборки с аргументами разрешения, сцены и выходной папки. Портовой сборке передаётся `--ui-audit-language`; старой — нет. Настройки `settings.ini` и `preferences.ini` инструмент сам не читает и не меняет, но игра использует их для языка и масштабов.

В обычном режиме результаты ячеек сохраняются в `out/old/<разрешение>/` и `out/new/<разрешение>/`: для запускаемой сцены — PNG и `.geometry.jsonl`. Листы попадают в `out/sheets/`, а сводка — в `out/reference.tsv`. В режиме с готовыми старыми PNG инструмент читает файлы вида `<old-png-dir>/<разрешение>/<сцена>.png`, старую сборку не запускает; в таблице код старого запуска и холст обозначены `-`. В режиме `--no-old` все поля старой стороны обозначены `-`.

В режиме `--gallery` создаются промежуточные снимки в `out/gallery-raw/`, готовые PNG копируются в `out/gallery/`, а результаты записываются в `out/gallery.tsv`. Сохранения, созданные игрой внутри папки ячейки, удаляются после захвата. Для безголового запуска задаются SDL-переменные и `XDG_DATA_HOME` внутри `out`.

### Лист «старое | новое»

Лист строится, если есть новый PNG. Ширина ячейки ограничена 1280 пикселями; обе картинки масштабируются до размеров, рассчитанных по новому PNG. Слева размещается старый снимок, справа — новый, между ними зазор; сверху — строка заголовка. Если старого PNG нет, слева создаётся тёмно-серая заглушка с текстом `no old scene`. Если нового PNG нет, лист не создаётся и в поле `sheet` ставится `-`.

### Проблемы ячейки и коды завершения

Для ячейки могут быть зафиксированы ненулевой код запуска (`exit=<код>`), неверный размер PNG, ненулевые `render_scale` или `world_scale`, а для старой стороны — несовпадение языка в заголовке. При таймауте после двух попыток записывается `timeout`. Также предусмотрены проблемы отсутствующего PNG, геометрии или каталожной сцены: `no-png`, `no-geometry`, `bad-geometry`, `no-scene`; для готового старого PNG — `old:no-png`. В `reference.tsv` проблемы помечаются `old:` или `new:` и соединяются точкой с запятой; в `gallery.tsv` префиксов нет. Отсутствие проблем обозначается `ok`.

Основной режим возвращает код 0, если все строки успешны, и 1, если хотя бы одна содержит проблему. Ошибки аргументов завершаются кодом 2. Для неуспешного `--ui-audit-list` описан `RuntimeError`, но отдельный код завершения инструмента для этого случая не задан.

### Прогоны, тесты и проверки

На сервере форк не собирают, потому что SDL2 отсутствует и устанавливать пакеты нельзя. Порт собирают заданной командой с выводом в `.tmp/out/`, затем запускают `reference_shots.py` в режиме «только новое» с `--headless --language ru`. Ожидается код 0, 31 строка данных в `reference.tsv`, у каждой `new_exit=0`, `problems=ok`, PNG соответствует разрешению и имеется лист. Ожидаемые холсты: 800×600 → 800×600, 1920×1080 → 1067×600, 5120×1440 → 2133×600. Все строки должны иметь `old_scene=-`. Если нужный размер PNG не получится, задание требует остановиться, а не подгонять снимок.

Отдельный серверный прогон `--gallery --language en` должен завершиться кодом 0 и создать пять PNG 1920×1080 с успешными строками `gallery.tsv`. Перед этим новые Python-тесты должны дать `Ran 25 tests` и `OK`; полный набор `tools/ui-audit/tests` тоже должен завершиться `OK`. Сборка порта должна завершиться кодом 0, а последняя строка CTest — сообщить `100% tests passed, 0 tests failed out of <N>` при `N > 345`.

Один пример теста: `test_timeout_is_retried_once` проверяет, что одна сцена, первый запуск которой завершается таймаутом, запускается повторно и проходит; а сцена, дважды завершившаяся таймаутом, записывается как `new_exit=timeout`, получает `new:timeout`, не порождает лист и приводит к результату `False`.

Проверки также требуют: не меньше 5000 МБ свободного места; проверки каталогов сцен с нулём отсутствующих портовых, форковых и галерейных сцен и с 192 сценами порта; успешной справки `--help` с перечисленными опциями; а в `git status` — только четыре новых файла из контракта. Python-прогоны и проверки каталогов описаны в тексте задания как команды с ожидаемыми кодами и выводами.

Команда для Windows, которую после сдачи запускает ведущий:

```text
python tools/ui-audit/reference_shots.py --out <OUT> --old-dir <OLD> --new-dir <NEW> --language ru --headless
```

`<OLD>` должен быть свежей распаковкой `v0.8.0-ru-hd.10` с `d2tm.exe` и ресурсами; в его `settings.ini` указано `Language=ru`, а `RenderScale=0` и `WorldScale` отсутствует либо равен 0. `<NEW>` — папка портовой сборки с `d2tm.exe`, `<OUT>` — новая пустая папка. Перед запуском в `%APPDATA%\D2TM\Dune II - The Maker\preferences.ini` ключи `RenderScale` и `WorldScale` должны отсутствовать или иметь значение 0.

### Двусмысленности и расхождения

Фраза «Для каждой пары … один запуск инструмента … даёт два снимка» допускает прочтение, что запускается отдельный процесс для каждой пары, и прочтение, что один вызов инструмента обрабатывает весь список пар. Я выбрал второе: это согласуется с заданным серверным вызовом без `--only`, который должен обработать все 31 ячейку.

Та же фраза обещает два снимка для каждой пары, но в списке есть две пары без сцены форка. Контракт отдельно предусматривает `old_png=None` и серую заглушку. Я выбрал такое поведение для `skirmish-hud` и `mentat-briefing-sardaukar`; реальных двух снимков у этих ячеек не будет.

В описании `run_gallery` сказано, что сцена проверяется через `list_scenes`, но сигнатура функции не принимает уже готовый каталог сцен. Это допускает внутренний вызов `list_scenes` в `run_gallery` или проверку вызывающим кодом. Я бы выбрал внутренний вызов, поскольку контракт требует проверить наличие сцены, а сигнатура не передаёт каталог.

**Расхождение с фактами о коде, названными в задании:** цель говорит: «для каждой пары … даёт два снимка», тогда как далее прямо указано, что у `skirmish-hud` и `mentat-briefing-sardaukar` нет сцены форка. Контракт с заглушкой разрешает это противоречие для реализации, но широкая формулировка цели остаётся неточной. Других явных противоречий между перечисленными в задании фактами о коде и его контрактом при одном прочтении я не вижу; сами файлы и поведение кода для этого пересказа не проверялись.
