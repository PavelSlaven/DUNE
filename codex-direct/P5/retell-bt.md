### Атаки

Ниже каждый красный случай — отдельная модификация реализации, в остальном исправной. Указание «проходит» относится к девяти описанным тестам; реальные прогоны не выполнялись.

#### Красные случаи: нарушение остаётся незамеченным

**К1. Меню не подключено к новым API.** Реализовать все проверяемые функции правильно, но оставить меню без новых строк и без вызова `saveScales` по Apply. Тесты **1–9** проходят, поскольку не открывают меню и не нажимают Apply; цель пользовательского шага не выполнена.

**К2. Заголовок совпадает по поведению, но не дословно.** В точной копии `OptionsMenuLayout.hpp` изменить только пробелы. Тесты **1–3** проверяют результаты вычислений, поэтому проходят; требование дословной копии нарушено.

**К3. Список рендеринга подогнан под шесть разрешений.** Для шести пар из теста вернуть предписанные векторы, для остальных — пустой список. Тест **4** проходит, но контракт требует вычислять результат через `ManualRenderScales` и `isManualRenderScaleAvailable` для всех аргументов.

**К4. Возвращается последний индекс совпадения.** Искать значение с конца и возвращать индекс последнего совпадения, при отсутствии — `0`. Тест **5** проходит, поскольку его векторы не содержат повторов; на `{0, 100, 100}` для `100` контракт требует `1`, а реализация вернёт `2`.

**К5. #### Зелёные случаи: перечисленный API выполнен, тест отвергает реализацию

**З1. Обычный `load` не читает `WorldScale`.** Выполнить все явно перечисленные требования: `save` записывает `WorldScale`, обе новые функции работают по контракту, но обычный `Preferences::load` оставляет `worldScalePercent` исходным. Тест **6** отвергает реализацию, ожидая `125` вместо исходного `0`; также расходятся ожидания тестов **7–8**.

Основание: приведённый контракт не требует менять обычный `load`. Это зелёный случай относительно **написанного раздела API**; утверждать, что он совместим с неизвестным существующим контрактом `load`, без исходников нельзя.

**З2. Обычный `load` требует полный файл настроек.** Все перечисленные функции реализованы правильно, включая создание `saveScales` файла ровно с двумя ключами, но обычный `Preferences::load` возвращает ошибку, если отсутствуют остальные обязательные для него настройки. Тест **8** падает на `REQUIRE(Preferences::load(...))`, хотя требования к `saveScales` выполнены.

Основание то же: предоставленный контракт не определяет, что обычный `load` обязан успешно читать файл только с двумя ключами и подставлять остальные значения по умолчанию. Такой результат задан тестом, но не разделом API.

Эти два зелёных случая показывают один пробел с двух сторон: тесты предъявляют дополнительные требования к обычному `Preferences::load`. Других доказанных зелёных случаев по предоставленному тексту я не установил; в частности, без исходников нельзя объявить ошибочными геометрические ожидания форка или число случаев матрицы.
