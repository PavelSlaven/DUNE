# Задание P1B — сборка свежего апстрима на Linux

## Цель

Скрипт сборки апстрима называется `tools/upstream/build_upstream_linux.sh`, принимает SHA базы апстрима аргументом и закрывает замечания 1, 2, 3 и 5 ревью шага Б1. Этим скриптом на servak собран и проверен апстрим `UP1 = d06f2fcd2a347182c3774fb96e9a85570405c489`: сборка без ошибок, все тесты CTest проходят, игра без окна доходит до главного меню.

Исходный код апстрима вне `tools/upstream/` не меняется.

## Рабочая копия

`/srv/dune/worktrees/b1` — отдельный клон, ветка `codex/p1b`, HEAD `7f25e7aa`. HEAD = `UP1` плюс один коммит, добавляющий прежний скрипт `tools/upstream/build_up0_linux.sh`.
- Зависимости и выход сборки — только внутри рабочей копии: `DUNE_DEPS_DIR=$PWD/.tmp/deps`, `DUNE_OUT_DIR=$PWD/.tmp/out`.
- Исходники зависимостей уже скачаны в `/srv/dune/deps/src` (только чтение). Сети нет.
- Журнал хода — `.tmp/p1b/progress.md`.

## Замечания ревью Б1, которые закрывает задание

1. Пропуск конфигурации опирается только на три значения `CMakeCache.txt`. После упавшей или прерванной конфигурации каждый следующий запуск пропускает `cmake`, и `make` падает.
2. Манифест SDL_image, SDL_ttf и SDL_mixer не включает манифест SDL. После смены SHA или опций SDL эти три библиотеки остаются собранными по старым заголовкам.
3. Бинарник копируется в `run/bin`, но запускается `build/d2tm`. Каталог `$DUNE_OUT_DIR/xdg` между запусками не обновляется, в отличие от `run/`.
4. Запасной путь `offscreen` ни разу не выполнялся. Код не меняется: в сдаче, в «Не проверено», указывается, выполнялась ли эта ветка.
5. Проверка базы падает, как только вне `tools/upstream` появится код форка. Для следующих шагов переноса скрипт непригоден.

## Шаги

1. **Вход.** Расхождение в любом пункте — блок `Q-P1B-01` со строками вывода и стоп.
   - `git rev-parse HEAD` начинается с `7f25e7aa`. `git rev-parse HEAD^` равен `UP1`. `git status --short` без строк `.tmp/` пуст.
   - `git diff --name-only UP1 HEAD` печатает ровно `tools/upstream/build_up0_linux.sh`.
   - `mkdir -p .tmp/deps && cp -a /srv/dune/deps/src .tmp/deps/src`. Каталоги `/srv/dune/deps/build`, `/srv/dune/deps/prefix` и `/srv/dune/deps/installed` не копируются.
2. **Скрипт.**
   - Переименуй файл командой `mv tools/upstream/build_up0_linux.sh tools/upstream/build_upstream_linux.sh`.
   - **Аргументы.** Внутренний режим `--dependency <лог> <имя>` остаётся как есть и разбирается первым. Публичный вызов принимает ровно один или ровно два аргумента. Первый — SHA базы апстрима, 40 шестнадцатеричных знаков. Второй, если он есть, — только `--pristine`. Любое другое число аргументов, первый аргумент не из 40 шестнадцатеричных знаков или второй аргумент не `--pristine` — скрипт печатает строку использования и выходит с кодом 2.
   - **Замечание 5.** Захардкоженный `up0=a51b97f1…` заменяется первым аргументом. Проверка `merge-base --is-ancestor <SHA> HEAD` выполняется всегда. Проверка `git diff --quiet <SHA> -- . ':(exclude)tools/upstream'` выполняется только с `--pristine`; без него скрипт печатает строку «Проверка чистоты базы пропущена».
   - **Замечание 1.** `cmake -S … -B …` для сборки апстрима выполняется при каждом запуске; условие пропуска по `CMakeCache.txt` удаляется.
   - **Замечание 2.** Манифест SDL_image, SDL_ttf и SDL_mixer включает содержимое файла `$DUNE_DEPS_DIR/installed/SDL`.
   - **Замечание 3.** Игра запускается как `./d2tm` с рабочим каталогом `$DUNE_OUT_DIR/run/bin`. Перед запуском прежний каталог `$DUNE_OUT_DIR/xdg`, если он есть, переносится в ту же папку лога, куда переносится прежний `run/`, под именем `previous-xdg`.
   - Тексты строк, которые ссылаются на UP0 («База UP0», «Обход UP0», «Конфигурация UP0»), называют базу «база апстрима». Строка-источник `src/game/cGame_logic.cpp:903–904` заменяется на `src/game/cGame_logic.cpp:945–946` — место в `UP1`, где печатается строка перехода в MENU; проверь это место поиском строки `Setting state from` в `src/`, при другом месте — блок `Q-P1B-01` с выводом поиска и стоп.
   - Других изменений скрипта нет.
3. **Первый прогон.** `DUNE_DEPS_DIR=$PWD/.tmp/deps DUNE_OUT_DIR=$PWD/.tmp/out bash tools/upstream/build_upstream_linux.sh d06f2fcd2a347182c3774fb96e9a85570405c489 --pristine` — в переднем плане, с таймаутом 30 минут.
   - Ожидается: код выхода 0; в итоге скрипта — строка тестов ctest с 0 упавших и строка MENU.
   - Код выхода не 0 — блок `Q-P1B-02` с последними 60 строками `full.log` и стоп. Так же — если для сборки нужна сеть, если CMake апстрима требует других версий SDL, чем закреплены в скрипте, или если строки перехода в MENU в логе игры нет (тогда приведи все строки лога игры со словом `state`). Ожидаемые тексты скрипта и закреплённые версии не меняй.
4. **Второй прогон** — та же команда.
   - Ожидается: код выхода 0; в логе каждая из пяти зависимостей — строка `SKIP_DEPENDENCY`; конфигурация апстрима выполнена (строка `Команда: cmake -S`); в папке лога есть `previous-run` и `previous-xdg`.
   - Иначе — блок `Q-P1B-03` со строками вывода и стоп.
5. **Отказы.** Каждая команда — с теми же переменными `DUNE_DEPS_DIR` и `DUNE_OUT_DIR`; запиши код выхода и последнюю строку вывода.
   - без аргументов — ожидается код 2;
   - `abc` — ожидается код 2;
   - `d06f2fcd2a347182c3774fb96e9a85570405c489 --other` — ожидается код 2;
   - `d06f2fcd2a347182c3774fb96e9a85570405c489 --pristine garbage` — ожидается код 2;
   - `a51b97f15d0eee2d323a1737f140eb2cbd60973c --pristine` — ожидается ненулевой код до сборки: `UP1` отличается от этой базы вне `tools/upstream`;
   - `0000000000000000000000000000000000000000` — ожидается ненулевой код до сборки.
   
   Другой код — находка в сдаче.

## Сдача

Блок `## DONE-P1B | <время UTC из date -u> | HEAD <sha>`. В нём:
- строки входа шага 1;
- `git diff --stat UP1 -- tools/upstream` и полный diff скрипта против прежнего `build_up0_linux.sh` (`git diff --no-index`, прежняя версия — из `git show HEAD:tools/upstream/build_up0_linux.sh`);
- из итога каждого из двух прогонов: версии зависимостей, строка ctest, строка запуска, строка MENU, путь `full.log`, время прогона;
- таблица шага 5: команда, ожидаемый код, полученный код, последняя строка;
- `### Коммиты` — одно английское сообщение `Take the upstream base as an argument in the Linux build script`; файлы — удалённый `tools/upstream/build_up0_linux.sh` и новый `tools/upstream/build_upstream_linux.sh`. В сообщении ровно один абзац `Behavior changes:`, он стоит перед завершающей строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Это исключение из правила раздела «Git» ниже о последней строке; повторять абзац запрещено;
- `### Не проверено` — в том числе, выполнялась ли ветка `offscreen` (замечание 4);
- `### git status --short`.

## Организация работы

- **Режим:** «Ведёт sol».
- **Порядок:** шаг 1 → шаг 2 → шаг 3 → шаг 4 → шаг 5 → `## DONE-P1B` и стоп.
- **Параллельно:** нет. Все прогоны пишут в один `$DUNE_OUT_DIR`, каждый шаг опирается на предыдущий.
- **Помощники:** нет; всё делает корневая нить.
- **Остановки:** только на `## DONE-P1B` и на блоках `Q-P1B-NN`.
- **Рамка правок:** `tools/upstream/build_up0_linux.sh` (удаляется переименованием), `tools/upstream/build_upstream_linux.sh` и `.tmp/`. Коммитов не делай.
