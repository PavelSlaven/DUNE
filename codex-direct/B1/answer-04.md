### 1. Проверка базы ломает скрипт после коммита (причина: исполнитель)

`build_up0_linux.sh:177–178` требует `HEAD == a51b97f…`. Скрипт будет закоммичен в ветку `codex/b1`, после этого `HEAD` — коммит со скриптом, и скрипт всегда завершается ошибкой «HEAD рабочей копии отличается от UP0». Проверять нужно то, что действительно важно: UP0 — предок `HEAD`, и отслеживаемые файлы вне `tools/upstream` в рабочем дереве совпадают с UP0.

Замени строки 175–178 (печать базы и проверку) на:

```bash
    up0=a51b97f15d0eee2d323a1737f140eb2cbd60973c
    printf 'База UP0: %s; HEAD: %s\n' "$up0" "$(git -C "$repo_root" rev-parse HEAD)"
    git -C "$repo_root" merge-base --is-ancestor "$up0" HEAD ||
        question 'UP0 не является предком HEAD.'
    git -C "$repo_root" diff --quiet "$up0" -- . ':(exclude)tools/upstream' ||
        question 'Отслеживаемые файлы вне tools/upstream отличаются от UP0.'
```

`git diff <коммит> -- <пути>` сравнивает рабочее дерево с коммитом, поэтому проверка верна и до коммита скрипта, и после. Неотслеживаемые `.tmp/` и игнорируемый `src/include/config.h` в сравнение не попадают.

Доказательство — две команды из корня рабочей копии, их вывод и коды выхода в сдаче:

```bash
git diff --quiet a51b97f15d0eee2d323a1737f140eb2cbd60973c -- . ':(exclude)tools/upstream'; echo "UP0: $?"
git diff --quiet a51b97f15d0eee2d323a1737f140eb2cbd60973c~1 -- . ':(exclude)tools/upstream'; echo "родитель UP0: $?"
```

Ожидание: `UP0: 0` и `родитель UP0: 1`. Код `1` у второй команды показывает, что проверка ловит отличие от UP0.

### 2. Скрипт пишет в репозиторий (причина: исполнитель)

`build_up0_linux.sh:8` создаёт `"$repo_root/.tmp/tmp"`, строка 11 ставит туда `TMPDIR`. Каталог `.tmp/` git не игнорирует, поэтому каждый запуск скрипта оставляет неотслеживаемый каталог в рабочей копии. Временные файлы — внутри выходного каталога:
- строка 8 — `mkdir -p "$DUNE_DEPS_DIR" "$DUNE_OUT_DIR/logs" "$DUNE_OUT_DIR/tmp"`;
- строка 11 — `export TMPDIR="$DUNE_OUT_DIR/tmp"`; она должна стоять после строки 10, где `DUNE_OUT_DIR` становится абсолютным путём.

Проверка `.tmp` (строки 31, 33, 37–39) — твой предел работы в песочнице, а не свойство скрипта. Удали из `check_disk` переменную `tmp_kib`, её расчёт, печать `du -sh "$repo_root/.tmp"` и проверку 12 ГБ. Проверку 6 ГБ для `DUNE_DEPS_DIR` и `DUNE_OUT_DIR` оставь. Предел 12 ГБ для всей `.tmp/` по-прежнему соблюдай сам, вне скрипта.

### 3. Внутренний маркер в выводе скрипта (причина: исполнитель)

`build_up0_linux.sh:16` печатает `## Q-B1 — …`. Это маркер протокола между тобой и ревьюером, а скрипт остаётся в проекте как инструмент. Замени строку 16 на:
