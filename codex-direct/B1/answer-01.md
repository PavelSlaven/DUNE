## PLAN-OK-B1 — с поправками и остановкой на дополнении

План одобрен с поправками 1–4 ниже. Поправки обязательны и заменяют соответствующие места плана и задания. Сейчас разрешён только этап «Исходники и опции» (поправка 2). Сборки, конфигурации CMake и установки начинаются только после моего ответа на `PLAN-B1-delta`.

### 1. Пути: всё внутри рабочей копии

Песочница этой нити разрешает запись только в `/srv/dune/worktrees/b1` и `/tmp`, а запускающий скрипт других корней записи не принимает. Поэтому вместо путей задания ты используешь такие:

| В задании | У тебя |
|---|---|
| `/srv/dune/deps` | `/srv/dune/worktrees/b1/.tmp/deps` |
| `/srv/dune/out/b1` | `/srv/dune/worktrees/b1/.tmp/out` |
| `/srv/dune/archive/b1-<время>/` | `/srv/dune/worktrees/b1/.tmp/archive/b1-<время>/` |

Скрипт `tools/upstream/build_up0_linux.sh` берёт каталог зависимостей из переменной окружения `DUNE_DEPS_DIR`, а каталог выхода — из `DUNE_OUT_DIR`. Если переменная не задана, значения такие: `/srv/dune/deps` и `/srv/dune/out/b1`. Ты каждый раз запускаешь скрипт так: `DUNE_DEPS_DIR=/srv/dune/worktrees/b1/.tmp/deps DUNE_OUT_DIR=/srv/dune/worktrees/b1/.tmp/out bash tools/upstream/build_up0_linux.sh`. Прогон со значениями по умолчанию после сдачи делаю я, вне песочницы.

Внутри `DUNE_OUT_DIR` раскладка такая:
- `build/` — каталог сборки UP0;
- `run/bin/` — рабочий каталог запуска игры;
- `xdg/` — значение `XDG_DATA_HOME` при запуске;
- `logs/` — логи скрипта.

Записи об успешной установке зависимостей лежат внутри `DUNE_DEPS_DIR`.

Диск:
- `.tmp/deps` и `.tmp/out` вместе занимают не больше 6 ГБ;
- вся `.tmp/` вместе с архивом занимает не больше 12 ГБ.

Больше — `Q`.

Перед последним полным прогоном с нуля `.tmp/deps` и `.tmp/out` переносятся в `.tmp/archive/b1-<время>/`.

### 2. Исходники и опции — этап до сборок

Сеть в этой нити включена. Сейчас разрешено ровно это:
1. Склонировать пять репозиториев по тегам из таблицы плана в `.tmp/deps/src/` (`git clone --branch <тег>`, `--depth 1` допустим).
2. Прочитать их `CMakeLists.txt`, файлы, где объявлены опции (например, в `cmake/`), и `.gitmodules`.
3. Скачать подмодули, нужные для выбранных встроенных библиотек. Условие: URL подмодуля в `.gitmodules` ведёт на `github.com/libsdl-org/*`. Если хост другой — `Q` до скачивания.

Затем пришли `## PLAN-B1-delta` и остановись.

В `PLAN-B1-delta`:
- таблица по каждой из пяти зависимостей: опция CMake, значение, файл и строка объявления опции в этой библиотеке по её тегу, зачем она (какой недостающей системной библиотеки касается или что отключает);
- форматы картинок, шрифтов и звука, которые загружает код UP0, — с файлом и строкой кода UP0, где идёт загрузка;
- список скачанных подмодулей: путь, URL, SHA;
- вывод `du -sh .tmp/deps` и `df -h /`.

Правило выбора опций:
- библиотеку, которой нет в системе (FreeType, PNG, ALSA, PulseAudio и другие отсутствующие, которые найдёшь), берёшь встроенной: подмодулем или встроенным декодером самой библиотеки;
- если встроенного варианта нет, а функция не нужна для сборки, тестов и запуска UP0 — выключаешь её;
- форматы, которые загружает код UP0, должны остаться включёнными;
- опции из `install_dependencies_ubuntu.sh:40–59` (`SDL_TEST_LIBRARY=OFF`, `SDLIMAGE_SAMPLES=OFF`, `SDLTTF_SAMPLES=OFF`, `SDLMIXER_SAMPLES=OFF`) задаёшь так же, как там.

### 3. Сборка UP0 — из рабочей копии, без копии исходников

Копию исходников в `.tmp/up0-src` не делай. Собирай из самой рабочей копии, как CI. Корень исходников скрипт вычисляет от собственного пути. Команды:

```bash
cmake -S <корень рабочей копии> -B "$DUNE_OUT_DIR/build" \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_PREFIX_PATH="$DUNE_DEPS_DIR/prefix"
make -C "$DUNE_OUT_DIR/build" -j16
```

`CMakeLists.txt:35–38` генерирует `src/include/config.h` в каталоге исходников. Этот файл игнорируется git (`.gitignore:25`), поэтому его появление правкой UP0 не считается. Рамка правок дополняется только этим файлом.

### 4. Запуск игры

Рабочий каталог собирается по `create_release.sh:13–56` в `$DUNE_OUT_DIR/run/bin/`, сам `create_release.sh` не исполняется — одобрено.

Критерий запуска не меняется. Должны выполниться оба условия:
- код выхода `timeout` — `124`;
- в логе игры есть строка, которую пишет вызов `src/game/cGame_logic.cpp:903–904` при переходе в состояние `MENU`.

Точный текст найденной строки — из прогона, в сдаче. Если строки нет (в том числе из-за буферизации лога), не меняй критерий и не правь код: `Q` с логом.

### Организация работы

- Порядок сейчас: клонирование пяти репозиториев → чтение опций → нужные подмодули → `PLAN-B1-delta` → стоп.
- Параллельно: пять клонов независимы; помощникам можно отдать клонирование и выписку объявлений опций по одной библиотеке.
- Помощники: не больше 3 одновременно, `gpt-6-luna` `xhigh`. Выбор опций — твой.
- Остановки: `PLAN-B1-delta`; `Q` — при подмодуле не с `github.com/libsdl-org/*`, превышении диска из поправки 1.
- Рамка правок: в рабочей копии — только `tools/upstream/build_up0_linux.sh`, `.tmp/` и сгенерированный `src/include/config.h`.
- Порядок после моего ответа на дополнение — как в разделе «Организация работы» плана.
- Журнал `.tmp/progress.md`: строка после клонирования и строка после отправки `PLAN-B1-delta`.

Остальное — по плану без изменений.
