# Задание U45R — разведка: металл ракетной установки, шов плиты, одинаковые флаги

## Цель

Собрать факты для трёх правок владельца. План по ним пишет ведущий. Задача только читает и замеряет: файлы вне `.tmp/u45r/` не меняются, коммитов нет, план не пишется, правки не делаются. Сборки, CTest и запуск игры запрещены.

Правки владельца:
1. У ракетной установки песочный цвет заменить на металлик, как у танка. Меняется только ракетная установка.
2. Горизонтальный шов посередине бетонной плиты сделать таким же тонким, как вертикальный.
3. Флаги на всех зданиях сделать как у Хранилища пряности: флаг целиком (шток, ткань, тень), тот же размер, та же анимация, все колышутся разом. Флаг ставится на нынешнее место флага каждого здания.

## Что выяснить

### А. Флаги

1. По каждой из 12 записей `BUILD_*_FLAG` пака `sdl_data_hd4.dat` и её маске `HM_BUILD_*_FLAG` выпиши:
   - размер записи, размер кадра и число кадров;
   - для кадра 0 — рамку пикселей с альфой больше 0;
   - рамку ткани, где ткань — пиксели с альфой больше 0, у которых зелёный канал больше красного и синего не менее чем на 30;
   - столбцы и строки штока: верх, основание, ширину;
   - рамку тени (полупрозрачные тёмные пиксели);
   - для каждого из кадров — рамку ткани, чтобы было видно, как ткань движется.
2. По каждой функции рисования флага в `src/drawers/cStructureDrawer.cpp` выпиши «файл:строка»:
   - как выбирается кадр: формула, таймер, период;
   - куда кладётся накладка;
   - как накладывается маска цвета Дома.
   Выпиши, чем различаются функции между собой. Причину «вразнобой» назови фактом «файл:строка»: свой таймер, своя фаза, своё число кадров или разная анимация ткани в кадрах.
3. Где используются `BUILDING_FLAG_LARGE` и `BUILDING_FLAG_SMALL` — «файл:строка» или «не используются».
4. Какой инструмент собрал каждую накладку флага и есть ли у неё мастер-файл в `resources/hd/master4/sdl_data/` — путь или «нет».
5. **Развилки с рекомендацией.** Перенос флага Хранилища (кадры штока, ткани и тени; маска) на место флага каждого здания:
   - как сопоставить место: основание штока Хранилища → основание штока здания;
   - что делать с тенью, которая у здания попадёт за край крыши;
   - как поступить с накладками шириной 384 (Перерабатывающий завод, Высокотехнологичный завод, Космопорт, Дворец) и с накладками на 3072 строки (Космопорт, Дворец);
   - нужна ли правка кода для синхронной анимации.
   Для каждого здания приложи кадр 0 тела здания с флагом Хранилища, перенесённым на основание его штока: `.tmp/u45r/flags/<здание>.png`, ×2 по ближайшему соседу, цвет Атрейдесов, на песке RGB (176, 138, 92).

### Б. Бетонная плита

1. `TERRAIN_SLAB` (5 тайлов 128 × 128), `PLACE_SLAB1`, `PLACE_SLAB4`. Для каждого тайла выпиши толщину тёмного шва по каждой из четырёх сторон в пикселях, цвет шва (медиана RGB) и цвет поля плиты (медиана RGB).
2. Как движок выбирает тайл плиты и укладывает тайлы рядом: «файл:строка». Выпиши, почему горизонтальный шов между соседями получается толще вертикального.
3. Мастер-файлы этих записей в `resources/hd/master4/` и инструмент, который их собрал, — пути или «нет».
4. Развилка с рекомендацией: как сделать горизонтальный шов той же толщины, что вертикальный, во всех трёх записях.

### В. Ракетная установка

1. `UNIT_LAUNCHER`, `HM_UNIT_LAUNCHER`, `UNIT_LAUNCHER_SHADOW` (8 направлений по 128 × 128). Найди песочные пиксели тела и выпиши правило, по которому ты их выделил. Выпиши их долю в каждом направлении, медиану RGB и покрывает ли их маска цвета Дома.
2. Металлические части танка (`UNIT_TANKBASE`, `UNIT_TANKTOP`): правило выделения, медиана RGB, разброс яркости (10-й и 90-й процентили).
3. Откуда берутся цвета ракетной установки во входах генерации `units-gen/UNIT_LAUNCHER/` и инструментах `tools/units3d/`: «файл:строка», имена текстур или материалов. Как пересобирается спрайт: команда, входы, выходы.
4. Развилка с рекомендацией:
   - перекраска во входах генерации и пересборка;
   - или перекраска пикселей готового спрайта по правилу.
   Приложи пробный лист `.tmp/u45r/launcher/probe.png`: направления 0, 2 и 5 из текущего пака и с пробной перекраской по рекомендованному способу, ×2, цвет Атрейдесов и Харконненов, на песке RGB (176, 138, 92).
5. Список других юнитов, у которых есть песочные части по тому же правилу: имя записи и доля песочных пикселей. Это только список для владельца, их не меняем.

## Организация работы

- **Порядок:** части А, Б и В одновременно → отчёт → сдача `DONE-U45R`.
- **Параллельно:** части А, Б и В не зависят друг от друга.
- **Помощники:** до 3, `gpt-6-luna` `xhigh`, без вложенных, по одному на часть. Корневая нить сама сводит отчёт и проверяет каждый факт помощника по «файл:строка» или по повторному замеру.
  - В бриф помощника дословно входят абзац «Комментарии в коде» ниже и запрет писать вне `.tmp/u45r/`.
- **Остановки:** только на сдаче `DONE-U45R` или на вопросе `Q-U45R-NN`.
- **Рамка правок:** только `.tmp/u45r/`. Ничего вне неё не меняй, не коммить.

## Комментарии в коде

Категорически запрещено писать комментарий по принципу «полезен, если верен и относится к делу». По умолчанию комментария нет; он должен доказать право на существование: только неочевидное «почему» — инвариант, причина обхода, ссылка на внешнее ограничение. Пересказ кода, планы и история — нет. Внутренние номера находок, планов и решений (`F7`, `A-11b`, `D88`) в комментарий не писать: суть словами.

Помощнику этот абзац передаётся в бриф дословно.
