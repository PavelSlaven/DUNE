# Задание P2G4 — вставка четырёх HD-рисунков в HD4-паки ветки порта

Режим: **«Ведёт sol»** (см. «Режимы задания» в конце). Исполнитель: корневая нить Codex `gpt-6.1-sol` `high`; вставку в паки делает один субагент `gpt-6-luna` `xhigh`.

Рабочая копия: `/srv/dune/worktrees/p2`, ветка `codex/p2g4`, `HEAD` — `80538936f` (слияние П2 в ветку порта `port/up-d06f2fcd`). В этой рабочей копии файлы Git LFS — настоящие данные: паки `resources/bin/data/*.dat` читаются и пишутся напрямую. Коммитов не делай: коммиты делает ведущий по списку из сдачи.

## Цель

Заменить в HD4-паках ветки порта четыре записи классики ×4 на готовые HD-рисунки и перевести приёмочные тесты П2 на эти рисунки.

## Что уже решено

Владелец решил нарисовать в HD четыре картинки, которые апстрим добавил и которых нет в HD4-паках форка. На шаге П2 эти картинки вошли в HD4-паки классикой, увеличенной в 4 раза: в `tests/data/hd4_packs_expected.tsv` у них столбец `source` равен `classic_x4`, столбец `sha256` равен `-`. Рисунки готовы и приняты ведущим. Каждый рисунок заменяет классику ×4 на той же позиции того же пака; имя, расширение и размер записи не меняются.

## Шаг 1. Приёмочные тесты — корневая нить сама

Исключение из правила «Существующие тесты и их ожидания не менять»: на шаге 1 корневая нить меняет ровно два файла ниже и ровно так, как описано. Субагент тесты не меняет.

**1а.** `tests/data/hd4_packs_expected.tsv`. В четырёх строках таблицы входов (строку находят по столбцам `pack` и `index`) столбец `sha256` получает SHA-256 файла из таблицы входов, столбец `source` получает значение `hd_drawing`. Остальные столбцы этих четырёх строк и все другие строки файла не меняются. Разделитель столбцов — табуляция; окончания строк — `\n`; файл кончается переводом строки `\n`.

Проверка: `git -c lfs.storage=$PWD/.tmp/p2g4/lfs diff --numstat -- tests/data/hd4_packs_expected.tsv` выводит ровно одну строку: `4`, табуляция, `4`, табуляция, `tests/data/hd4_packs_expected.tsv`.

**1б.** `tools/upstream/tests/test_port_packs_data.py`:

1. Сразу после словаря `CLASSIC_WITHOUT_HD` добавь словарь:

   ```python
   HD_DRAWINGS = {
       "sdl_data_hd4.dat": ["EXPLOSION_CARRYALL"],
       "sdl_inter_hd4.dat": ["BMP_SELECT_HOUSE_SARDAUKAR", "ICON_POWER_LOW"],
       "sdl_mentat_hd4.dat": ["MENTATS"],
   }
   ```

2. Метод `test_hd4_pack_entries_and_classic_x4_pixels` переименуй в `test_hd4_pack_entries` и измени так:
   - без изменений остаются проверки: множество паков ожидаемой таблицы равно множеству ключей `TAG_COUNTS`; число записей пака равно числу строк; число строк с `source` = `fork` равно `TAG_COUNTS[pack]`; `(index, name, extension)` записи равны значениям строки; `entry.index` равен порядковому номеру записи; размер картинки равен `width` и `height` строки;
   - новая проверка для каждого пака: список значений столбца `name` строк с `source` = `hd_drawing`, в порядке строк таблицы, равен `HD_DRAWINGS.get(pack, [])`;
   - строка с `source` = `fork` или `source` = `hd_drawing`: SHA-256 полезной нагрузки записи равен значению столбца `sha256` строки;
   - строка с любым другим значением `source`: тест падает через `self.fail`, текст сообщения содержит это значение `source`;
   - ветка `classic_x4` удаляется целиком: переменная `classics`, чтение классического пака, `decode_image`, `scale_image` и сравнение пикселей.
3. Остальное в файле не меняется. `CLASSIC_WITHOUT_HD` и `tools/upstream/classic_without_hd.json` не меняются: они записывают вход шага выравнивания П2.

## Шаг 2. Красный прогон и заморозка тестов — корневая нить

1. Из корня рабочей копии: `/srv/dune/venv/bin/python -m unittest discover -s tools/upstream/tests -v > .tmp/p2g4/tests-red.log 2>&1`.
2. Ожидается всё сразу: строка `Ran 43 tests`; итоговая строка `FAILED (failures=4)`; ровно четыре заголовка, начинающихся с `FAIL: test_hd4_pack_entries`, по одному на каждое имя из `HD_DRAWINGS`; каждый из четырёх провалов — несовпадение SHA-256; ни одного заголовка `ERROR:`; ни одного пропущенного теста. Иначе — блок `## Q-P2G4-02` с итоговыми строками лога и заголовками провалов, и стоп.
3. Заморозка: `sha256sum tests/data/hd4_packs_expected.tsv tools/upstream/tests/test_port_packs_data.py > .tmp/p2g4/tests.sha256`. После этой команды корневая нить и субагент два файла тестов не меняют.

## Шаг 3. Вставка рисунков в паки — субагент `gpt-6-luna` `xhigh`

Субагент пишет скрипт `.tmp/p2g4/insert.py` и запускает его из корня рабочей копии: `/srv/dune/venv/bin/python .tmp/p2g4/insert.py > .tmp/p2g4/insert.log 2>&1`. Скрипт делает по порядку:

1. Читает три пака `resources/bin/data/sdl_data_hd4.dat`, `resources/bin/data/sdl_inter_hd4.dat`, `resources/bin/data/sdl_mentat_hd4.dat` функцией `tools.hd_assets.read_pack`; аргумент — объект `pathlib.Path`.
2. Для каждой строки таблицы входов проверяет: у записи пака с этим индексом имя равно имени записи из таблицы, расширение равно `PNG`, SHA-256 файла из `.tmp/p2g4/final/` равен SHA-256 из таблицы. Хоть одна проверка не прошла — скрипт печатает строку таблицы и найденные значения, завершается кодом 1 и не пишет ни одного файла.
3. Только после того как прошли проверки всех четырёх строк, для каждой строки заменяет запись на `tools.hd_assets.PackEntry` с тем же индексом, именем и расширением; полезная нагрузка — байты файла, прочитанные как есть, без декодирования и перекодирования картинки. Остальные записи остаются теми же объектами.
4. Пишет три пака на их же места функцией `tools.hd_assets.write_pack`.
5. Перечитывает три пака и печатает по каждому паку: число записей до и после; число записей, у которых `(index, name, extension, payload)` отличается от прочитанного в пункте 1; по каждой заменённой записи — индекс, имя и SHA-256 новой полезной нагрузки. Ожидается: число записей до и после равно; число отличающихся записей — 1 у `sdl_data_hd4.dat`, 2 у `sdl_inter_hd4.dat`, 1 у `sdl_mentat_hd4.dat`; SHA-256 каждой новой полезной нагрузки равен SHA-256 из таблицы входов. Иначе — код 1.

Субагент меняет только три пака и пишет только в `.tmp/p2g4/`. Сдача субагента корневой нити: код выхода скрипта и полный вывод `.tmp/p2g4/insert.log`.

## Шаг 4. Зелёный прогон и проверки — корневая нить

1. `sha256sum -c .tmp/p2g4/tests.sha256` — `OK` для обоих файлов. Иначе — блок `## Q-P2G4-03` и стоп.
2. `/srv/dune/venv/bin/python -m unittest discover -s tools/upstream/tests -v > .tmp/p2g4/tests-green.log 2>&1` — строка `Ran 43 tests`, итоговая строка `OK`, ни одного пропущенного теста. Иначе — блок `## Q-P2G4-04` с заголовками провалов и стоп.
3. Сборка Linux. Перед сборкой `df -m /srv`: в столбце `Available` не меньше 5000, иначе блок `## Q-P2G4-05` и стоп. Команда из корня рабочей копии: `DUNE_DEPS_DIR=$PWD/.tmp/deps DUNE_OUT_DIR=$PWD/.tmp/out bash tools/upstream/build_upstream_linux.sh d06f2fcd2a347182c3774fb96e9a85570405c489 > .tmp/p2g4/build.log 2>&1`. Успех: код выхода 0, в `ctest.log` из папки `.tmp/out/logs/` тест чтения HD4-паков в состоянии `Passed`, а не `Skipped`. Иначе — блок `## Q-P2G4-06` с последними 40 строками `.tmp/p2g4/build.log` и стоп.
4. `git -c lfs.storage=$PWD/.tmp/p2g4/lfs status --short` выводит ровно пять строк, по одной на файл, каждая начинается с ` M `: `resources/bin/data/sdl_data_hd4.dat`, `resources/bin/data/sdl_inter_hd4.dat`, `resources/bin/data/sdl_mentat_hd4.dat`, `tests/data/hd4_packs_expected.tsv`, `tools/upstream/tests/test_port_packs_data.py`. Любая другая строка — блок `## Q-P2G4-07` с выводом и стоп.

## Сдача

Последнее сообщение — блок `## DONE-P2G4 | <время UTC из date -u> | HEAD <sha>` по форме из правил ниже. В нём:

- `## PLAN-P2G4` для записи: шаги по порядку и кто их делал;
- вывод `sha256sum -c .tmp/p2g4/final.sha256`;
- строки красного прогона: `Ran`, итоговая строка, четыре заголовка `FAIL:`;
- содержимое `.tmp/p2g4/tests.sha256`;
- вывод `.tmp/p2g4/insert.log`;
- строки зелёного прогона: `Ran` и итоговая строка; вывод `sha256sum -c .tmp/p2g4/tests.sha256`;
- код выхода сборки и строки `ctest.log` об итоге и о тесте чтения HD4-паков;
- список коммитов: два пункта. Пункт 1 — оба файла тестов, сообщение на английском о переводе приёмочных тестов П2 на HD-рисунки. Пункт 2 — три пака, сообщение на английском о замене классики ×4 четырьмя HD-рисунками. Последняя строка каждого сообщения — `Behavior changes: …`.

Оценку облика рисунков не делай. Числа в сдаче — только из вывода команд.

## Организация работы

- **Порядок:** сверка входов → шаг 1 → шаг 2 → шаг 3 → шаг 4 → сдача.
- **Параллельно:** нет. Каждый шаг зависит от предыдущего: красный прогон — от правки тестов, вставка — от заморозки тестов, зелёный прогон — от вставки.
- **Помощники:** не больше двух субагентов `gpt-6-luna` `xhigh`, без вложенных. Субагент 1 делает шаг 3; его бриф дословно содержит раздел «Входы» (таблица и путь папки), раздел «Шаг 3» целиком и абзац «Комментарии в коде». Субагент 2 запускает команды прогонов шагов 2 и 4 дословно и сдаёт корневой нити коды выхода и строки логов, перечисленные в этих шагах; его бриф дословно содержит команды и ожидания шагов 2 и 4 и абзац «Комментарии в коде». Правку тестов на шаге 1, заморозку, сверку результатов с ожиданиями и сдачу делает корневая нить.
- **Остановки:** только на `## DONE-P2G4` и на блоках `## Q-P2G4-NN`. Команда оболочки дважды подряд не завершилась (нет кода выхода) — блок `## Q-P2G4-08` и стоп.
- **Рамка правок:** `tests/data/hd4_packs_expected.tsv`, `tools/upstream/tests/test_port_packs_data.py`, три пака из таблицы входов, папка `.tmp/p2g4/`. Сборка пишет в `.tmp/out/` и `.tmp/deps/`; это не правка. Другие файлы рабочей копии не меняй.
