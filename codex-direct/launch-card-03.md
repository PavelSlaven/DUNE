# Карточка запуска: B1 — базовая сборка апстрима UP0

Снимок: 2026-10-28, 20:10 UTC. Ветка с заданиями: `units3d/pilot`.

## Что и зачем

Шаг Б1 текущего плана (закреплённый issue #1, `docs/PLAN_units_sega_upstream.md` §6): собрать чистый апстрим `UP0` (`a51b97f1`) на Windows (MSYS2, SDL3) и Linux, прогнать его тесты и запустить игру. Это база для переноса функций форка (Б3–Б12): без рабочей сборки апстрима нельзя отличить ошибку переноса от ошибки окружения. B0 принят — карта переноса в ветке `codex/b0`.

## Что требует UP0 (проверено по коду `a51b97f1`)

- CMake ≥ 3.21; SDL3, SDL3_image, SDL3_ttf, SDL3_mixer; тесты — Catch2, 15 файлов в `tests/` (`tests/CMakeLists.txt`), прогон `ctest`.
- Linux в CI апстрима: `install_dependencies_ubuntu.sh` ставит системные пакеты через `sudo apt` и собирает из исходников SDL 3.4.10, SDL_image 3.4.4, SDL_ttf 3.2.2, SDL_mixer 3.2.4 с установкой в `/usr/local`.
- Windows в CI апстрима: MSYS2 MINGW64, пакеты из `.github/workflows/build_pr.yml`: `mingw-w64-x86_64-toolchain`, `-gcc`, `-sdl3`, `-sdl3-mixer`, `-sdl3-image`, `-sdl3-ttf`, `-cmake`, `-catch`.

## Что есть сейчас

- servak: Debian 13, CMake 3.31, g++ 14; SDL3 нет; в apt есть `libsdl3-dev` 3.2.10, `-image` 3.2.4, `-ttf` 3.2.2, а `sdl3-mixer` нет. Docker хранит образы на `/srv/qwen-serving` — это диск твоего сервиса, поэтому Docker не используем. На корне свободно 19 ГБ.
- ПК: MSYS2, CMake и компилятора нет.
- Форк публичный, Actions включены. Но workflow апстрима `build_master` публикует релиз при push в `master`, а `build_manual` — при ручном запуске. Поэтому CI форка для Б1 не используем: риск выпустить релиз в форке.
