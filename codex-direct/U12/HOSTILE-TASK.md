# Задание U12-H — враждебное чтение задания U12

Режим: **«Ведёт sol»**: плана не присылай, сразу работай и сдай `## DONE-U12-H`. Исполнитель: Codex `gpt-6.1-sol` `high`; помощники — субагенты `gpt-6-luna` `xhigh`.
Рабочая копия: `/srv/dune/worktrees/u9f` — только чтение. Файлы не создавай и не меняй нигде, кроме ответа.

## Цель

Найти в тексте задания U12 (`/srv/dune/tasks/u12-h/U12-TASK.md`) места, где буквальное исполнение даёт неверный результат, до того как его получит исполнитель.

## Что сделать

1. Прочитай задание U12 и эталонный скрипт `/srv/dune/tasks/u12/lead-rotation.py`. Код, на который задание ссылается, — в рабочей копии: `tools/units3d/redraw_build.py`, `tools/units3d/redraw_common.py`, `tools/units3d/redraw.py`, `codex-direct/U6/squads/compose.py`, `codex-direct/U6/JOURNAL.md`, `tools/units3d/units/*/unit.json`.
2. Найди и запиши:
   - **Ложный зелёный**: дословное исполнение каждого пункта, при котором проверки задания проходят, а цель не достигнута (размер машин по направлениям не выровнен, пехота стоит не на высоте классики, команда `rotation` считает не то, что эталон, тест не ловит названную неверную реализацию).
   - **Ложный красный**: честное исполнение, которое текст задания отвергает или останавливает (условие, которое не может выполниться на настоящих данных; противоречие двух пунктов; проверка, которую нарушает сама предписанная формула или механизм `place` в `redraw_common.py`).
   - **Два прочтения**: фраза, которую можно исполнить двумя способами с разным результатом.
   - **Атаки на тесты пунктов 2 и 4**: для каждого теста — неверная реализация, которую он не ловит, и честная, которую он отвергает, если они есть.
3. Для каждой находки: цитата из задания, как её прочтёт исполнитель, что получится, предложенная формулировка. Числа и утверждения о коде — с путём и строкой файла; утверждение о данных — с командой, которой ты его проверил (только чтение, без временных файлов: песочница запрещает запись).

## Чего не делать

- Не правь файлы рабочей копии и задание; не запускай `build`, `pack` и тесты, которые пишут в рабочую копию.
- Не оценивай, нужна ли сама задача и верны ли числа поправок: это решение ведущего и владельца. Числа поправок проверяй только на то, совпадают ли они с выводом эталонного скрипта.

## Сдача

Блок `## DONE-U12-H | <время UTC из date -u>`: находки списком по четырём видам из пункта 2, в каждой — поля пункта 3; раздел «Не проверено».

## Организация работы

- Порядок: `create_goal` → чтение → поиск находок → сдача.
- Параллельно: пункты 1–10 задания U12 проверяются независимо — раздай группы пунктов помощникам одновременно.
- Помощники: субагенты `gpt-6-luna` `xhigh` — чтение кода и задания по группам пунктов, проверочные команды только для чтения. Сводка и итог — твои.
- Рамка правок: правок нет; единственный выход — ответ.
- Остановки — блок `## Q-U12-H-NN` и стоп: файл из пункта 1 не читается.
