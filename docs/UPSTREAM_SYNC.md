# Обновление порта с апстрима

Порт живёт на коде апстрима `stefanhendriks/Dune-II---The-Maker`. Обновление выполняется слиянием свежего `master` апстрима в ветку порта, а не повторным переносом функций.

## Когда обновлять

Обновляйте порт после каждого выпуска апстрима или раз в месяц, если в `master` апстрима появились новые коммиты.

## Шаги

1. Получите свежий `master` апстрима на сервере: `git -C /srv/dune/worktrees/u63 fetch https://github.com/stefanhendriks/Dune-II---The-Maker.git master`. Запишите `FETCH_HEAD` как цель обновления.
2. Сформируйте отчёт: `python3 tools/upstream/upstream_sync_report.py --repo /srv/dune/worktrees/u63 --base <последний слитый SHA апстрима> --target <цель> --port <вершина ветки порта> --out <папка>`. Последний слитый SHA апстрима — второй родитель последнего коммита слияния апстрима в ветке порта. Найдите его командой `git log --merges --format='%H %P' <ветка порта>`; на момент записи это `d7869e710fc5a91e8e217a3d387767428d82e07d`.
3. По отчёту ведущий пишет задание на разрешение конфликтов (образец — `codex-direct/P14/TASK-P14A.md`). Укажите правило «устройство кода — апстрима, поведение порта сохраняется», добавьте таблицу по каждому файлу раздела «Пробное слияние» и список файлов без конфликта, которые ссылаются на удалённое апстримом.
4. Ведущий создаёт рабочую копию от вершины порта и начинает слияние командой `git merge --no-ff --no-commit <цель>`. Исполнитель только правит файлы; коммит слияния делает ведущий.
5. До коммита проверьте, что маркеров конфликта нет; сборка `tools/upstream/build_upstream_linux.sh` завершилась с кодом 0; все тесты CTest зелёные и ни один тест порта не пропал; каталог сцен режима отладки интерфейса содержит те же идентификаторы; все ячейки команды `tools/ui-audit/reference_shots.py --no-old --headless` имеют статус `ok`.
6. Создайте PR в ветку порта, дождитесь зелёного CI на Windows, Linux и macOS, затем выполните слияние.

## Что ломается чаще всего

- Апстрим удаляет имена заголовков, констант или записей паков, а файлы порта продолжают на них ссылаться без конфликта слияния.
- Скрипты ищут строки журнала игры; например, `tools/upstream/build_upstream_linux.sh` проверяет строку состояния `MENU`.
- Изменение паков апстрима меняет ожидаемые тестами данные в `tests/data/classic_packs_expected.tsv`.
