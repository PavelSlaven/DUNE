# Конвейер `tools/units3d/` — спецификация поведения

Статус: черновик ведущего для заданий A2б (приёмочные тесты) и A2а (реализация). Числа, помеченные «пилот», утверждает владелец на пилоте; до утверждения действуют значения по умолчанию из этого документа.

Источник размеров, порядка направлений, правил отрисовки и света — контракт `docs/units/unit_contract.json` (задание A1). Где этот документ и контракт расходятся, прав контракт; расхождение — вопрос ведущему.

## 1. Система координат и камера

- Мир: `X` — восток, `Y` — север, `Z` — вверх. Модель после импорта glTF в Blender стоит на плоскости `Z = 0` (координаты Blender после импорта, ось `Z` вверх).
- Камера ортографическая, смотрит с юга на север и вниз под углом `θ` к горизонту: направление «от цели к камере» — `(0, −cos θ, sin θ)`. Верх экрана — север. Экранная проекция точки: `x_экр = X`, `y_экр (вверх) = Y·sin θ + Z·cos θ`.
- `θ` — поле `elevation_deg` в `resources/hd/units3d/common/camera.json`. По умолчанию 63 (пилот: выбор из 55, 60, 63, 67, 72).
- Масштаб один на все юниты: `hd4_px_per_m` в `camera.json` — пикселей HD4 на метр модели. По умолчанию 16 (пилот).
- Направление `k` (столбец атласа) — поворот модели вокруг вертикальной оси на угол `yaw_k` против часовой стрелки, если смотреть сверху; `yaw = 0` — нос на восток. Соответствие столбца и `yaw` берётся из `column_meaning` контракта (ожидается E=0°, NE=45°, N=90°, NW=135°, W=180°, SW=225°, S=270°, SE=315°).
- Ожидаемый экранный угол носа для `yaw` и `θ`: `atan2(sin(yaw)·sin θ, cos(yaw))`, 0° — вправо, 90° — вверх.

## 2. Исходники юнита

Папка `resources/hd/units3d/<ключ>/`, где `<ключ>` — имя атласа корпуса без префикса `UNIT_` в нижнем регистре (`tankbase`, `devastator`). В ней:

- `source/*.glb` — модель (Git LFS);
- `unit.json` — манифест:

```json
{
  "parts": {
    "body": {"atlas": "UNIT_TANKBASE", "shadow": "UNIT_TANKBASE_SHADOW", "mask": "HM_UNIT_TANKBASE"},
    "top":  {"atlas": "UNIT_TANKTOP", "mask": "HM_UNIT_TANKTOP"}
  },
  "model": "source/desert_tank.glb",
  "forward": "-Y",
  "length_m": 7.0,
  "pivot_xy": [0.0, 0.05],
  "pivot_height_ratio": 0.5,
  "split": {
    "turret": [{"type": "cylinder", "center_xy": [0.0, 0.05], "radius": 0.14, "z_min": 0.16},
               {"type": "box", "min": [-0.03, -0.49, 0.18], "max": [0.03, -0.1, 0.26]}],
    "cap_z": 0.16
  },
  "house_zones": [{"type": "box", "min": [-0.2, -0.3, 0.1], "max": [0.2, 0.3, 0.2]}],
  "mask_share": [0.08, 0.35],
  "max_holes": 0
}
```

Поля:
- `parts` — какие записи пака строятся. У юнита без башни есть только `body`. Записи, которых нет в `parts`, конвейер не трогает.
- `forward` — ось носа модели после импорта (`+X`, `−X`, `+Y`, `−Y`). Конвейер поворачивает модель так, чтобы нос смотрел на `+X`.
- `length_m` — длина модели по оси носа после масштабирования, в метрах. Масштаб модели = `length_m / длина по оси носа до масштабирования`.
- `pivot_xy` — ось вращения в координатах модели до масштабирования (после поворота носа на `+X`). Для юнита с башней — центр кольца башни: корпус и башня вращаются вокруг одной оси, поэтому центр кольца стоит в одном пикселе во всех кадрах.
- `pivot_height_ratio` — доля высоты корпуса, на которой лежит точка оси, попадающая в центр кадра. Центр кадра — `(w/2, h/2)` в пикселях кадра.
- `split` — для модели одной сеткой: грани, центр которых попал в любой из объёмов `turret`, — башня, остальные — корпус. Отверстие в корпусе под башней закрывается плоской крышкой на высоте `cap_z` по контуру отверстия; низ башни закрывается так же. Без `split` модель — одна деталь `body`.
- `house_zones` — объёмы в координатах модели; грани, центр которых внутри объёма, — зона цвета Дома. Пустой список — маска не строится (запись маски из `parts` удаляется из сборки с ошибкой, а не тихо).
- `mask_share` — коридор доли пикселей маски от непрозрачной площади кадра (пилот).
- `max_holes` — допустимое число дыр в силуэте корпуса.

Общие файлы `resources/hd/units3d/common/`:
- `camera.json`: `elevation_deg`, `hd4_px_per_m`, `supersample` (рендер в `supersample ×` размере кадра HD4, затем Lanczos; по умолчанию 2);
- `light.json`: направление солнца (азимут и высота) — азимут выбирается так, чтобы экранное направление тени юнита совпало с медианой `light` контракта ±10°; сила света; цвет;
- `render.json`: версия Blender (`5.2.3`), движок `CYCLES`, устройство `CPU`, число сэмплов, `seed`, шумоподавление.

## 3. Команды

Все команды запускаются из корня репозитория; пути аргументов — относительно него.

1. Рендер: `blender -b --factory-startup --python tools/units3d/render_unit.py -- --unit resources/hd/units3d/<ключ> --out <папка>`
2. Сборка атласов: `python tools/units3d/build_atlases.py --unit resources/hd/units3d/<ключ> --render <папка рендера> --out <папка атласов>`
3. Установка в пак: `python tools/units3d/install.py --atlases <папка атласов> --pack <путь к sdl_data_hd4.dat>` — заменяет записи по именам из манифеста атласов, остальные записи пишет побайтно прежними (`read_pack`/`write_pack` из `tools/hd_assets.py`).
4. Проверка: `python tools/units3d/check_unit.py --unit resources/hd/units3d/<ключ> --atlases <папка атласов> --contract docs/units/unit_contract.json` — проверки раздела 5; код выхода 0 только если все прошли; вывод — строка на проверку: номер, имя, `PASS`/`FAIL`, числа.

## 4. Выход

Папка рендера (`--out` команды 1), на каждую деталь `<part>` (`body`, `top`) и направление `k = 0…7`:
- `<part>/color_<k>.png` — RGBA, размер `frame_hd4 × supersample`;
- `<part>/mask_<k>.png` — зоны Дома: RGB = 255 там, где зона, альфа = покрытие пикселя; вне зоны (0,0,0,0); рендерится только эта деталь;
- `<part>/markers_<k>.png` — служебный проход: на чёрном прозрачном фоне три маленькие светящиеся сферы диаметром 4 пикселя рендера: красная (255,0,0) — точка носа на оси симметрии на высоте `pivot_height`, зелёная (0,255,0) — точка оси вращения на высоте `pivot_height`, синяя (0,0,255) — центр кольца башни на высоте `cap_z` (у юнита без башни синей нет);
- `body/shadow_<k>.png` — тень всего юнита (корпус и башня носом вперёд) на ловце теней; модель в этом проходе камере не видна; RGB = (0,0,0), альфа = плотность тени, масштабированная так, чтобы максимум альфы был 51 (как у нынешних теней `UNIT_*_SHADOW`, которые движок рисует с прозрачностью `ShadowTrans = 160`);
- `render_manifest.json` — версия Blender, `θ`, хэши SHA-256 файлов `camera.json`, `light.json`, `render.json`, `unit.json` и модели, размеры, масштаб модели, экранная длина корпуса по оси носа в пикселях HD4 (из геометрии).

Папка атласов (`--out` команды 2):
- по PNG на каждую запись из `parts` (атлас, тень, маска): 8 кадров в строку в порядке столбцов контракта, размер кадра — `frame_hd4` контракта, кадр получен из рендера фильтром Lanczos;
- `atlases.json` — имя записи → файл, размер, SHA-256; хэши общих файлов и `render_manifest.json`.

## 5. Проверки `check_unit.py` (они же приёмочные тесты)

Непрозрачный пиксель — α > 16. Пиксели — HD4, если не сказано иначе. Маркер — центр масс пикселей своего цвета в `markers_<k>.png`, переведённый в HD4 (деление на `supersample`).

| № | Проверка | Порог |
|---|---|---|
| 1 | Размер каждого атласа = `columns × frame_hd4[0]` на `rows × frame_hd4[1]` контракта | точно |
| 2 | После `install.py` в паке изменены только записи из `atlases.json`; все прочие записи побайтно прежние; число записей и их порядок прежние | 0 лишних изменений |
| 3 | Экранный угол вектора «зелёный → красный маркер» в кадре `k` = ожидаемый угол из раздела 1 | ±3° |
| 4 | Зелёный маркер во всех 8 кадрах корпуса в одной точке; синий маркер во всех кадрах корпуса и башни в одной точке | ±1 px |
| 5 | Ни один непрозрачный пиксель атласа и тени не ближе 2 px к краю кадра | 0 пикселей |
| 6 | Длина непрозрачной области кадра E корпуса по оси x = экранная длина корпуса из `render_manifest.json` | ±5 % |
| 7 | Нет пикселей с α < 8 и RGB ≠ 0; непрозрачная область корпуса в каждом кадре — одна связная область (8-связность); дыр не больше `max_holes` | 0 нарушений |
| 8 | Маска: каждый пиксель маски с α > 0 лежит на непрозрачном пикселе своего атласа; в каждом кадре маска не пуста; доля в коридоре `mask_share` | 100 % / коридор |
| 9 | Тень: RGB всех пикселей с α > 0 равен (0,0,0); максимум α = 51 ±2; угол вектора «центр масс корпуса → центр масс тени» в кадре E = медиана угла `light` контракта | ±10° |
| 10 | Хэши общих файлов и `unit.json` в `atlases.json` равны хэшам текущих файлов | равенство |
| 11 | Повторный прогон команд 1–2 на той же машине: ≥ 99,9 % пикселей каждого атласа совпадают, разница канала ≤ 2 | порог |

Снимки в игре (п. 5.1 №12 плана) делает ведущий; в этот скрипт они не входят.

## 6. Что конвейер не делает

Не генерирует модели и текстуры; не выбирает `θ`, масштаб, зоны Дома и параметры разрезки — их задают файлы в `resources/hd/units3d/`; не меняет движок и классические паки.
