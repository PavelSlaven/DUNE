# Конвейер `tools/units3d/` — спецификация поведения

Статус: черновик ведущего. По спеке Codex пишет проверки (задание A2b), ведущий Claude — команды 1–3 (решение Р9 в `docs/decisions.md`). Числа, помеченные «пилот», утверждает владелец на пилоте; до утверждения действуют значения по умолчанию из этого документа.

Источник размеров, порядка направлений, правил отрисовки и света — контракт `docs/units/unit_contract.json` (задание A1). Где этот документ и контракт расходятся, прав контракт; расхождение — вопрос ведущему.

## 1. Система координат и камера

- Мир: `X` — восток, `Y` — север, `Z` — вверх. Модель после импорта glTF в Blender стоит на плоскости `Z = 0` (координаты Blender после импорта, ось `Z` вверх).
- Камера ортографическая, смотрит с юга на север и вниз под углом `θ` к горизонту: направление «от цели к камере» — `(0, −cos θ, sin θ)`. Верх экрана — север. Экранная проекция точки: `x_экр = X`, `y_экр (вверх) = Y·sin θ + Z·cos θ`.
- `θ` — поле `elevation_deg` в `resources/hd/units3d/common/camera.json`. `θ = 63` — решение владельца Р12 (`docs/decisions.md`).
- Масштаб один на все юниты: `hd4_px_per_m` в `camera.json` — пикселей HD4 на метр модели. По умолчанию 16 (пилот).
- Направление `k` (столбец атласа) — поворот модели вокруг вертикальной оси на угол `yaw_k` против часовой стрелки, если смотреть сверху; `yaw = 0` — нос на восток. Соответствие столбца и `yaw` берётся из `column_meaning` контракта (ожидается E=0°, NE=45°, N=90°, NW=135°, W=180°, SW=225°, S=270°, SE=315°).
- Ожидаемый экранный угол носа для `yaw` и `θ`: `atan2(sin(yaw)·sin θ, cos(yaw))`, 0° — вправо, 90° — вверх.

## 2. Исходники юнита

Папка `resources/hd/units3d/<ключ>/`, где `<ключ>` — имя атласа корпуса без префикса `UNIT_` в нижнем регистре (`siegebase`, `devastator`). В ней:

- `source/*.glb` — модель (Git LFS);
- `unit.json` — манифест; пример — фактический `resources/hd/units3d/siegebase/unit.json`:

```json
{
  "parts": {
    "body": {"atlas": "UNIT_SIEGEBASE", "shadow": "UNIT_SIEGEBASE_SHADOW", "mask": "HM_UNIT_SIEGEBASE"},
    "top": {"atlas": "UNIT_SIEGETOP", "mask": "HM_UNIT_SIEGETOP"}
  },
  "model": "source/desert_tank.glb",
  "forward": "-Y",
  "frame_hd4": [144, 144],
  "atlas_hd4": [1152, 152],
  "length_m": 7.0,
  "pivot_xy": [-0.07, 0.0],
  "pivot_height_ratio": 0.5,
  "split": {
    "turret": [
      {"type": "box", "min": [-0.31, -0.15, 0.225], "max": [0.18, 0.15, 0.45]},
      {"type": "box", "min": [0.1, -0.06, 0.24], "max": [0.5, 0.06, 0.36]}
    ],
    "cap_z": 0.225,
    "cap_color": [133, 112, 85]
  },
  "house_paint": {"hue_deg": 30, "hue_width_deg": 18, "min_saturation": 0.18, "min_value": 0.27},
  "mask_share": [0.79, 0.99],
  "max_holes": 0
}
```

Поля:
- `parts` — какие записи пака строятся. У юнита без башни есть только `body`. Записи, которых нет в `parts`, конвейер не трогает.
- `model` — путь к модели относительно папки юнита.
- `forward` — ось носа модели после импорта (`+X`, `−X`, `+Y`, `−Y`). Конвейер поворачивает модель так, чтобы нос смотрел на `+X`.
- `frame_hd4` — размер кадра HD4 `[w, h]`; равен `frame_hd4` записи атласа в контракте.
- `atlas_hd4` — размер PNG каждой записи из `parts` `[W, H]`; равен `hd4_size` этой записи в контракте. 8 кадров стоят в верхней строке слева направо; остальная площадь (если `H > frame_hd4[1]`) прозрачная `(0,0,0,0)`.
- `decimate` (необязательное, по умолчанию 1.0) — доля граней, которую оставляет модификатор Decimate (Collapse) Blender до любой другой обработки.
- `length_m` — длина модели по оси носа после масштабирования, в метрах. Масштаб модели = `length_m / длина по оси носа до масштабирования`.
- `pivot_xy` — ось вращения в координатах модели до масштабирования (после поворота носа на `+X`). Для юнита с башней — центр кольца башни: корпус и башня вращаются вокруг одной оси, поэтому центр кольца стоит в одном пикселе во всех кадрах.
- `pivot_height_ratio` — доля высоты корпуса, на которой лежит точка оси, попадающая в центр кадра. Центр кадра — `(w/2, h/2)` в пикселях кадра.
- `split` — для модели одной сеткой: грани, центр которых попал в любой из объёмов `turret`, — башня, остальные — корпус. Отверстие в корпусе под башней закрывается плоской крышкой на высоте `cap_z`; низ башни закрывается так же. Без `split` модель — одна деталь `body`.
  - Объём — `{"type": "box", "min": [x, y, z], "max": [x, y, z]}` или `{"type": "cylinder", "center_xy": [x, y], "radius": r, "z_min": z}` (ось цилиндра вертикальна, снизу он ограничен `z_min`, сверху не ограничен). Объёмы `turret` и `house_zones` и значение `cap_z` заданы в координатах модели до масштабирования (после поворота носа на `+X`).
  - `split.cap_color` — цвет крышки корпуса под башней, sRGB 0–255. Крышка всегда входит в зону Дома целиком (сила 1), потому что видна при повороте башни (решение владельца Р11).
- `house_paint` — зона цвета Дома по краске модели: тексель базового цвета (значения файла текстуры в sRGB, без перевода в линейное пространство; HSV в шкале 0–1) считается краской, если круговое расстояние его тона до `hue_deg` меньше `hue_width_deg` (в градусах), насыщенность больше `min_saturation` и яркость больше `min_value`. Решение владельца Р11: в цвет Дома красится вся краска модели.
- `house_zones` (необязательное) — объёмы в тех же координатах. Если поле есть, краской могут быть только грани, центр которых лежит в одном из объёмов; если поля нет или список пуст — все грани модели.
- `mask_share` — коридор `[нижняя, верхняя]` доли маски по формуле проверки 8, границы включены. Ставится по замеру атласов, одобренных владельцем: от минимума доли по всем маскам и кадрам юнита минус 0.05 до максимума плюс 0.05, с округлением наружу до 0.01.
- `max_holes` — допустимое число дыр в силуэте корпуса.

Общие файлы `resources/hd/units3d/common/`:
- `camera.json`: `elevation_deg`, `hd4_px_per_m`, `supersample` (рендер в `supersample ×` размере кадра HD4, затем Lanczos; по умолчанию 2);
- `light.json` — свет сцены:
  - `sun_azimuth_deg` (130) — направление на солнце в плоскости `XY`, в градусах от оси `+X` (восток) против часовой стрелки, если смотреть сверху; вектор на солнце — `(cos(высота)·cos(азимут), cos(высота)·sin(азимут), sin(высота))`. Азимут выбирается так, чтобы экранное направление тени юнита совпало с медианой `light` контракта ±10°;
  - `sun_elevation_deg` (76) — высота солнца над горизонтом в градусах. Выбрана так, чтобы тень ствола Осадного в направлениях E и S помещалась в кадр 144×144 с полем не меньше 2 px;
  - `sun_strength` — сила солнца (параметр `Strength` источника Sun в Blender);
  - `sun_color` — цвет солнца `[R, G, B]`, 0–1;
  - `sun_angle_deg` — угловой диаметр диска солнца в градусах; чем больше, тем мягче край тени;
  - `ambient_color` — цвет равномерного света неба `[R, G, B]`, 0–1;
  - `ambient_strength` — сила света неба (параметр `Strength` фона мира Blender);
- `render.json`: `blender` (версия Blender, `5.2.3`), `engine` (`CYCLES`), `device` (`CPU`), `samples` (число сэмплов проходов цвета и тени), `mask_samples` (число сэмплов проходов маски и маркеров), `seed`, `denoise` (шумоподавление).

## 3. Команды

Все команды запускаются из корня репозитория; пути аргументов — относительно него.

1. Рендер: `blender -b --factory-startup --python tools/units3d/render_unit.py -- --unit resources/hd/units3d/<ключ> --out <папка> [--directions <список k через запятую>] [--passes <color,mask,markers,shadow>] [--elevation <градусы>]`. Три необязательных аргумента нужны только для листов сравнения; атласы строятся без них.
2. Сборка атласов: `python tools/units3d/build_atlases.py --unit resources/hd/units3d/<ключ> --render <папка рендера> --out <папка атласов>`
3. Установка в пак: `python tools/units3d/install.py --atlases <папка атласов> --pack <путь к sdl_data_hd4.dat>` — заменяет записи по именам из манифеста атласов, остальные записи оставляет прежними: те же имена, расширения, порядок и байты содержимого (`read_pack`/`write_pack` из `tools/hd_assets.py`).
4. Проверка: `python tools/units3d/check_unit.py --unit resources/hd/units3d/<ключ> --render <папка рендера> --atlases <папка атласов> --contract docs/units/unit_contract.json [--pack-before <пак до> --pack-after <пак после>] [--allow-skip 2]` (маркеры и `render_manifest.json` берутся из папки рендера) — проверки 1–10 раздела 5; вывод — строка на проверку: номер, имя, `PASS`/`FAIL`/`SKIP`, числа.

   Дополнительно `--pack-before <пак до> --pack-after <пак после>`: оба вместе или ни одного; один без другого — ошибка аргументов, код 2. Без них проверка 2 печатает `SKIP`, и код выхода ≠ 0, если не передан `--allow-skip 2`. Приёмка ведущим всегда идёт с обоими аргументами пака и без `--allow-skip`. Ошибка чтения входа даёт `FAIL` с причиной у каждой проверки, читающей этот вход; скрипт печатает строки всех проверок и не завершается исключением. Код выхода 0 — только если все проверки `PASS` (или `SKIP` проверки 2 при `--allow-skip 2`).

## 4. Выход

Папка рендера (`--out` команды 1), на каждую деталь `<part>` (`body`, `top`) и направление `k = 0…7`:
- `<part>/color_<k>.png` — RGBA, размер `frame_hd4 × supersample`;
- `<part>/mask_<k>.png` — зоны Дома; маска рендерится этой деталью одной: грань вне зоны — прозрачная (holdout); грань зоны — белая с покрытием, равным доле краски (`house_paint`); крышка — белая целиком;
- `<part>/markers_<k>.png` — служебный проход, размер как у `color_<k>.png`: каждая сфера рендерится в отдельном проходе одна, без модели и других сфер; диаметр сферы 4 пикселя рендера; покрытие (альфа) этого прохода записывается в свой канал: R — сфера носа, G — сфера оси, B — сфера кольца башни (у юнита без башни B = 0); A = максимум из R, G, B. Сфера носа — точка носа на оси симметрии на высоте `pivot_height`, сфера оси — точка оси вращения на высоте `pivot_height`, сфера кольца — центр кольца башни на высоте `cap_z`. Красный маркер проверок — канал R, зелёный — G, синий — B;
- `body/shadow_<k>.png` — тень всего юнита (корпус и башня носом вперёд) на ловце теней; модель в этом проходе камере не видна; тень только от солнца: в этом проходе сила света неба (`ambient_strength`) равна 0, иначе рассеянный свет даёт полупрозрачный ореол до краёв кадра; RGB = (0,0,0), альфа = плотность тени;
- `render_manifest.json` — версия Blender (`blender`), `θ` (`elevation_deg`), `hd4_px_per_m`, `supersample`, размеры кадра (`frame_hd4`), масштаб модели (`model_scale`), `pivot_height_m`, `cap_height_m`, экранная длина корпуса по оси носа в пикселях HD4 из геометрии (`hull_screen_length_px`), `parts`, `directions`, `bbox_hd4` и `hashes`. `bbox_hd4` — для каждой детали и k экранный охватывающий прямоугольник вершин детали в пикселях HD4, вычисленный из геометрии: `bbox_hd4[<деталь>][<k>] = [xmin, ymin, xmax, ymax]` в непрерывных координатах кадра (y вниз, центр кадра — `(w/2, h/2)`); ширина — `xmax − xmin`, высота — `ymax − ymin`. `hashes` — SHA-256 файлов с ключами `camera.json`, `light.json`, `render.json`, `unit.json` и `model` (файл модели).

Папка атласов (`--out` команды 2):
- по PNG на каждую запись из `parts` (атлас, тень, маска): размер `atlas_hd4`; 8 кадров стоят в верхней строке слева направо в порядке столбцов контракта, размер кадра — `frame_hd4`; остальная площадь прозрачная `(0,0,0,0)`. Кадр получен из кадра рендера так: `PIL.Image.resize((frame_hd4[0], frame_hd4[1]), Image.LANCZOS)` над RGBA, затем канонизация в этом порядке: (1) у каждого пикселя атласа, тени и маски с α < 8 все четыре канала обнуляются; (2) у каждого пикселя маски, под которым пиксель атласа своей детали имеет α ≤ 16, все четыре канала обнуляются; (3) у тени после шагов (1) и (2) α всех 8 кадров умножается на общий множитель `51 / (максимум α по всем 8 кадрам тени)` и округляется (`numpy.round`, `float32`), так что максимум по всем 8 кадрам равен 51 (как у нынешних теней `UNIT_*_SHADOW`, которые движок рисует с прозрачностью `ShadowTrans = 160`); RGB тени = (0,0,0). Проверки 5–10 применяются к окончательным кадрам после канонизации;
- `atlases.json` — точный формат: `{"entries": {<имя записи>: {"file": <имя PNG>, "size": [W, H], "sha256": <hex>}}, "hashes": {"camera.json": …, "light.json": …, "render.json": …, "unit.json": …, "render_manifest.json": …}}`.

## 5. Проверки `check_unit.py` (они же приёмочные тесты)

Непрозрачный пиксель — α > 16. Пиксели — HD4, если не сказано иначе. Координаты непрерывные: пиксель кадра рендера с индексами (i, j) имеет центр ((i + 0.5)/s, (j + 0.5)/s) в пикселях HD4, где s = `supersample`; y растёт вниз. Маркер — среднее центров пикселей с весом значения канала этого маркера; файл, в котором канал этого маркера пуст (все значения 0), — FAIL проверки, которая его читает. Проверки 3–4 выполняются для каждой детали из `parts` и каждого k = 0…7. До сравнения ничего не округляется. Экранный угол вектора (dx, dy) в координатах изображения — `atan2(−dy, dx)` в градусах (0° — вправо, 90° — вверх, как в §1). Разность углов a и b — `((a − b + 180) mod 360) − 180`; сравнивается её модуль. Круговая медиана — угол из набора, у которого сумма модулей разностей с остальными углами наименьшая. Нулевой вектор или нечисловой результат — FAIL.

| № | Проверка | Порог |
|---|---|---|
| 1 | Состав и размеры. R — имена из `parts` файла `unit.json` (`atlas`, `shadow`, `mask` каждой детали). Каждое имя из R есть в контракте. Его `role` соответствует месту в `parts`: `body.atlas` → `body`, `top.atlas` → `top`, `body.shadow` → `shadow`, `body.mask` → `mask_body`, `top.mask` → `mask_top`. Поле `mask` детали равно `house_mask` её атласа в контракте. Поля `unit_types` у всех записей R одинаковы. У записи `columns = 8`; `frame_hd4` в `unit.json` равен `frame_hd4` записи в контракте. Ключи `atlases.json` в точности равны R; JSON разбирается с проверкой повторяющихся ключей. Каждый файл существует, читается как PNG RGBA и имеет размер `atlas_hd4` из `unit.json`, равный `hd4_size` записи в контракте, причём `atlas_hd4[0] = 8 · frame_hd4[0]` и `frame_hd4[1] ≤ atlas_hd4[1] < 2 · frame_hd4[1]`; иначе FAIL с причиной «не поддерживается». Последовательность пар (имя, расширение) после установки равна последовательности до установки. У каждой записи не из R байты содержимого равны прежним; смещения в каталоге могут измениться. У каждой записи из R байты содержимого равны байтам файла, который ей назначает `atlases.json` (этот файл прошёл проверки 1, 5–10). ## 6. Что конвейер не делает

Не генерирует модели и текстуры; не выбирает `θ`, масштаб, зоны Дома и параметры разрезки — их задают файлы в `resources/hd/units3d/`; не меняет движок и классические паки.
