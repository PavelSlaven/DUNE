# План переноса форка на апстрим `d06f2fcd` (волна 4)

Источник решений:
- Р4 — функции переносятся по одной, история связывается `merge -s ours`, без force-push;
- Р34 — игра грузит только HD4;
- Р63 — волна 4;
- Р64 — исключение для `<cmath>`.

Источник шагов — `docs/PLAN_units_sega_upstream.md` §3.2 (поток Б), проверки — там же, §5.3. Функции, пути, риски и порядок — `docs/upstream/PORT_MAP.md`. Карточка запуска — `codex-direct/launch-card-27.md`: шаги П2–П15 запускаются без новых карточек; смена подхода или рамки — новая карточка.

## 1. Цель и готовность

Перенос готов, когда выполнены все условия:
1. `main` построен на апстриме `UP1` = `d06f2fcd2a347182c3774fb96e9a85570405c489` и догнан до свежего master апстрима (шаг П14). `git merge-base --is-ancestor` истинен и для апстрима, и для `6662b2f4`.
2. Все 23 функции карты перенесены, каждая — своим шагом, своей веткой и своим PR в ветку порта.
3. Выполнены проверки §5.3 № 1–10 плана.
4. Владелец принял новую сборку в игре до перемотки `main`.
5. Выпущен релиз `v0.9.x-ru-hd`. Номер выбирает владелец.

## 2. Ветка порта и сборки

- Ветка порта — `port/up-d06f2fcd` на GitHub. Сейчас это `UP1` плюс скрипт `tools/upstream/build_upstream_linux.sh`.
- У каждого шага своя ветка `codex/pN` от вершины ветки порта и свой PR в ветку порта. PR открывается после проверок раздела 3 с автослиянием (Р67).
- `main` до шага П14 получает только документы процесса и карту переноса (Р63). Единственное исключение — Р64.
- **Сборка Linux** — на servak, на жёстком диске `/srv/library/dune` (Р77): рабочая копия шага — `/srv/library/dune/worktrees/pN`, библиотеки — общий набор `DUNE_DEPS_DIR=/srv/library/dune/deps` (собран ведущим, нити его только читают; `LD_LIBRARY_PATH=/srv/library/dune/deps/prefix/lib`); команда: `DUNE_OUT_DIR=$PWD/.tmp/out bash tools/upstream/build_upstream_linux.sh d06f2fcd2a347182c3774fb96e9a85570405c489`, без `--pristine`, потому что на ветке шага есть код форка. Успех: код 0, все тесты CTest проходят, игра доходит до строки перехода в MENU.
- **Сборка Windows** — на ПК (MSYS2 в `C:\msys64`, SDL3). Механику делает субагент Sonnet, логи — в scratchpad. Успех: сборка без ошибок, все тесты CTest проходят, игра доходит до MENU.
- **CI** — workflows апстрима на PR в ветку порта. Проверка `claude-review` падает до решения владельца на шаге П12 (раздел 6); остальные проверки должны пройти. CI берёт файлы без LFS, поэтому тесты, которые читают HD4-паки, в CI пропускаются; они проходят в сборках Linux и Windows.
- **LFS на ветке порта** — только для путей, которые добавляет форк (с П2 — `resources/bin/data/*_hd4.dat` и `resources/bin/data/scenes/hd4/*.dat`). Файлы апстрима остаются обычными файлами git: слияния с апстримом не дают конфликтов «файл против указателя LFS».

Правила цикла:
- Разведку пропускает только шаг, все факты которого уже собраны в карте и прошлых отчётах. Ведущий записывает это в задание.
- Замечания проверки сдачи исправляет та же нить исполнителя по ответу ведущего. Исправления проверяют скрипты и субагенты Haiku. Codex сдачи не проверяет и не утверждает.
- На каждом запуске: проверка задания `check-literal.py --task` отдельным шагом, ожидатель ответа, надзор раз в 30 минут со скриптом проверки загрузки Codex. Надзор удаляется, когда исполнитель не работает.
- Свободное место на servak — не меньше 5000 МБ, иначе стоп. Временные папки закрытого шага ведущий удаляет только после согласия владельца (список — в отчёте о слиянии).

## 7. Организация работы

- **Порядок:** шаги — по таблице раздела 4; внутри шага — этапы а–ж раздела 3.
- **Параллельно:** шаги из столбца «Параллельно» раздела 4 запускаются одновременно (Р77): П8, П9, П10 и П11 — сразу после П7, каждый своей нитью `gpt-6.1-sol` в своей рабочей копии на `/srv/library/dune`; задания пишутся пачкой, пересказы идут одновременно, проверка на Windows — вместе с CI. Шаги, которые меняют одни и те же файлы, идут по очереди. Порядок их слияния в ветку порта — по номеру шага.
- **Помощники:** задание шага делит механику на независимые дорожки и даёт каждой дорожке одного помощника `gpt-6-luna` `xhigh`. Все дорожки запускаются сразу, одновременно не больше трёх, без вложенных помощников. Корневая нить делает суждение и итоговую сверку.
- **Остановки:** исполнитель останавливается только на сдаче `DONE` и на вопросе `Q`. Ведущий останавливает шаг при свободном месте на servak меньше 5000 МБ, при необратимом действии и при вопросе владельцу из раздела 6.
- **Рамка правок:** задание шага называет файлы. Код вне рамки, приёмочные тесты и `main` до шага П14 исполнитель не меняет.
